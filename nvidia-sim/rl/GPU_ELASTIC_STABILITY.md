# 낮은 물리 주파수의 탄성 식물 안정성

> 후속 변경: 사용자가 960Hz와의 정밀 일치보다 실용적인 접촉·걸림·탄성 동작을
> 우선하도록 기준을 변경했다. 기능 검사를 거쳐 GPU dataset 기본값을 60Hz preset으로
> 변경했다. 이후 49번의 가는 줄기 관통을 확인하여 contact120으로 다시 변경했다.
> 최신 설정/범위는 [CONTACT_PENETRATION_FIX.md](CONTACT_PENETRATION_FIX.md)를 읽는다.
> 아래는 이전의 엄격한 동등성 검사 기록으로 보존한다.

기존 주파수·CPU 병렬화 작업은 `1305651`에 커밋했다. 아래는 후속 안정성 실험이다.
장면 배치, 충돌 도형, 줄기 분할 수, 질량, 스프링 강성·감쇠, 마찰, 꼭지 파손
임계값은 유지했다. 로봇 명령은 모든 설정에서 60Hz다. RL/DR은 사용하지 않았다.

**판정: 낮은 Hz의 정지 안정성은 개선했지만, 기존 물리 결과를 유지하는 대체
설정은 아직 검증되지 않았다. 기본값은 960Hz / armature 1e-5를 유지한다.**
특히 armature 1e-3은 960Hz에서 로봇 접촉 전 비목표 연결부가 파손되어 채택하지 않았다.

## 바꾼 것

관절의 **armature(보조 관성)**를 명시적으로 설정할 수 있게 했다.
이는 실제 식물 조직의 측정 관성이 아니라, 가느다란 관절 모델의 수치적 안정성을
돕는 추가 관성이다. 정적 스프링 상수를 바꾸지 않지만 과도 응답과 충격 응답은
달라질 수 있다. 기존 데이터와 동일한 물리 모델이라고 간주하면 안 된다.

```bash
# 기존 기준 설정: 기본값은 그대로 유지
./nvidia-sim/run_gpu_candidate_dataset.sh \
  --physics-preset reference960 --num-envs 4 --candidates 8 --schedule continuous \
  --physics-hz 960 --elastic-joint-armature 0.00001

# 진단 목적의 실험 설정: 원래 모델과 다른 응답이며 동등성 검사를 통과하지 않음
./nvidia-sim/run_gpu_candidate_dataset.sh \
  --physics-preset reference960 --num-envs 4 --candidates 8 --schedule continuous \
  --physics-hz 240 --elastic-joint-armature 0.0001
```

설정은 `config.json`, `backend.json`, 후보의 `physical_inputs.backend`에 기록한다.
실제 PhysX DOF armature가 요청값과 같은지 검사한다. 다른 설정으로 기존 데이터셋을
이어 쓰는 것은 허용하지 않는다. CPU 경로 사전 계산은 기존처럼 최대 8개 worker다.

## 분리 진단

240Hz, 로봇 정지, 최대 2초의 시험에서:

- 기존 설정: 줄기/연결부 물리 바디 최대 이동 약 58.5mm.
- 중력과 초기 하중을 함께 제거: 약 0.072mm.
- 충돌만 제거: 약 32.4mm. 따라서 충돌만으로 설명되지 않는다.
- 초기 하중을 목표 각도나 목표 속도로 옮긴 드라이브 방식: 불안정 또는 초기 파손.
  채택하지 않았다. `gpu_probe_worker.py --preload-mode`는 진단용으로만 남긴다.
- 기존 고정 하중 방식을 유지하고 armature를 1e-4로 조정: 약 0.43mm.
- armature 1e-3: 240Hz 약 0.10mm, 60Hz 약 0.50mm.

단순한 정지 안정성 개선만으로 접촉 정확도를 보장하지 않으므로,
동일 명령 재생과 하중을 가했다가 제거하는 시험을 추가했다.

## 접촉·복원 및 시간 간격 검증

저장된 `candidate_00003`의 동일한 로봇 명령을 재생했다. 4환경은 같은 명령의 복제다.
모든 아래 실행은 첫 비목표 잎 접촉 후 과도 변위로 중단됐다. 성공 고리걸기나
전체 수확 모션의 완료 시간은 아니다. 초기화 시간은 표에서 제외했다.

| 설정 | 1환경 계산 시간 | 4환경 계산 시간 | 시뮬레이션 시간 |
|---|---:|---:|---:|
| 기존 960Hz / 1e-5 | 156.25초 | 168.69초 | 4.333초 |
| 480Hz / 1e-4 | 79.54초 | 88.31초 | 4.350초 |
| 240Hz / 1e-4 | 40.83초 | 47.90초 | 4.383초 |
| 60Hz / 1e-3 | 11.74초 | 17.32초 | 4.350초 |
| 240Hz / 1e-3 | 40.18초 | 46.90초 | 4.317초 |

물리 모델 및 종료 시점이 다르므로 이 비율은 **유효한 동등성 speedup이 아니다**.
정지 시 안정해 보여도 접촉·파손 응답이 달라질 수 있다.

목표 꼭지 끝에 초기 자세 기준 0.2N에 해당하는 토크를 1초 동안 주고 제거한
4초 시험에서는 다음 차이가 있었다. 0.1초 간격으로 기록한 목표 과실 변위다.

| 설정 | 최대 변위 | 4초 시점 잔류 변위 |
|---|---:|---:|
| 기존 960Hz / 1e-5 | 37.64mm | 11.80mm |
| 240Hz / 1e-4 | 21.39mm | 3.08mm |
| 60Hz / 1e-3 | 16.56mm | 0.66mm |
| 240Hz / 1e-3 | 15.41mm | 0.33mm |

토크 제거 뒤 돌아오는 현상은 확인했지만, 같은 변형 응답은 아니다.
강성 수치가 같다는 이유로 원래 물리 모델과 동등하다고 해석하지 않는다.

보조 관성을 **동일하게 고정**하고 Hz만 바꾼 검증도 수행했다.

- 1e-4의 960Hz와 240Hz: 첫 접촉과 실패 분류는 같지만, 고리 간격 최대 차이
  3.83mm, 주줄기 변위 지표 차이 2.67mm, 종료 시점 차이 3제어 스텝.
  사전에 정한 1mm / 1제어 스텝 기준을 통과하지 못했다.
- 1e-4의 960Hz와 480Hz: 고리 간격 최대 차이 1.96mm, 주줄기 변위 지표 차이
  1.37mm, 종료 시점 차이 1제어 스텝. 오차는 줄었지만 1mm 기준은 넘었다.
- 1e-3의 960Hz: 첫 제어 스텝(0.0167초)에
  `/World/envs/env_0/HarvestJoint_05_4`가 파손됐다. 로봇 첫 접촉은 없었다.
  이 설정에서는 높은 주파수를 안정적인 기준으로 쓸 수도 없다.
  파손 임계값을 높이거나 파손 판정을 꺼서 통과시키지 않았다.

240Hz / 1e-4와 60Hz / 1e-3을 각각 실제 데이터셋 실행기에 넣어
4환경·8개의 서로 다른 후보·후보당 16제어 스텝을 실행했다.
RGB-D, 초기 상태/독립 reset, 실제 armature 적용, CPU 경로 worker 연동이 통과했다.
짧은 배선 검사이므로 두 실행 모두 **8개 `incomplete`**, `dataset_complete=false`다.
이는 고리걸기 성공 검증이 아니다.

수치와 검증 범위: [검증 JSON](validation/gpu_elastic_stability.json).
원본 명령·상태·접촉 기록은 `runs/20260921_150500_elastic_diagnosis/`와
`runs/20260921_151000_elastic_validation/`에 저장했다. 후자의
`*_harness_error` 폴더는 진단 코드 오류로 실패한 초기 실행이며 결과에서 제외했다.
오류 수정 후 `pulse_960`, `pulse_240`, `pulse_60`으로 다시 실행했다.

따라서 당장 적용할 수 있는 검증된 성능 개선은 앞선 CPU 경로 병렬화다.
저주파 물리는 진단 옵션으로 남기고, 이후에는 파손 연결부를 포함한 관절 하중 전달과
실측 변형 응답을 검증해야 한다. 960Hz 기준도 실물 정답으로 보증된 것은 아니다.

## 진단 도구

`gpu_probe_worker.py`에 아래 옵션을 추가했다.

- `--joint-armature`: 진단용 보조 관성.
- `--no-gravity`, `--no-preload`: 정지 시험에서만 사용 가능한 원인 분리.
- `--preload-mode effort|drive|velocity`: 기본은 원래 `effort`.
- `--pulse-force 0.2`: 초기 Jacobian에서 목표 꼭지 부위에 world-X 방향 0.2N을
  가하는 것과 동등한 **고정 관절 토크**를 계산하여, 0.5~1.5초 사이에만 추가한다.
  변형 중인 부위에 일정한 공간 힘을 계속 가하는 시험이나 실제 고리 접촉 시험과는 다르다.
  줄기 움직임을 강제로 지정하거나 원위치로 복귀시키지 않는다.

실패한 probe는 이제 비정상 종료 코드를 반환한다. 비교 도구는 armature가 다른 두
시험을 기존 모델의 동등한 가속으로 판정하지 않는다. 접촉/reset/파손 API 검사가
실패한 실행 역시 속도 개선으로 채택하지 않는다.
