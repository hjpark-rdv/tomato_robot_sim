# RGB + joint 근접 접근 실험

> **대상 불일치 정정:** 최초 보고의 ROI는 Tomato_05가 아니라 Tomato_06을 추적했다.
> 목표 토마토 밀림 감지 성공이라는 기존 해석을 철회한다. 아래 과거 수치는 다른 열매를
> 추적한 실행의 물리 결과다. 기본 ROI를 Tomato_05로 수정했다. 재실행에서는 접촉 전 특징점이 7개로 줄어
> `tracking_lost`로 중단됐다. 올바른 목표의 밀림 감지는 아직 검증하지 못했다.

기존 greenhouse와 탄성 주줄기/송이를 유지한 Tomato_05 실험이다. 도구에 고정한
RGB 카메라로 토마토·꽃받침의 움직임을 관찰하고, 관절값으로 예상한 카메라 움직임과
맞지 않는 영상 변화가 지속되면 정지 후 후퇴한다. 힘 센서, depth, 접촉 대상 ID,
시뮬레이터의 토마토/줄기 위치는 제어 입력으로 사용하지 않는다.

**고리걸기 성공 정책이나 RL 학습 결과가 아니다.** 이전 경로를 그대로 실행할 때
식물이 밀리는 것을 감지하고 접근을 중단하는 첫 단계다.

## 실행

```bash
# GUI; DISPLAY=:0 사용 가능. 항상 2x 영상을 저장한다.
DISPLAY=:0 ./nvidia-sim/run_rgb_guard.sh
# 화면 없이 동일한 RGB 렌더링/물리 실행
./nvidia-sim/run_rgb_guard.sh --headless
# 감지해도 경로를 끝까지 실행하는 비교군
./nvidia-sim/run_rgb_guard.sh --headless --rgb-action baseline
# 기존 카메라와 좌우 후보를 동시에 기록
./nvidia-sim/run_ring_rl.sh --mode rgb --rgb-action compare --headless
```

출력은 `rl/runs/YYYYmmdd_HHMMSS_rgb_guard_tomato05/`에 저장한다. 물리 시간 간격은
1/960초, 제어 60 Hz, 영상 관측 30 Hz다. 30 Hz 프레임을 60 fps로 인코딩하여
재생만 2배속으로 만든다. `--rgb-replay-rate`는 물리 속도를 바꾸는 별도 실험 옵션이며
녹화 배속 옵션이 아니다. 기본값 1을 검증했다.

## 카메라와 추적

- `current`: URDF의 D435 RGB 외부 파라미터, 기존 near clipping 10 cm를 재현한다.
  이것은 렌더러 설정이며 실제 RGB 카메라의 초점 한계를 뜻하지 않는다.
- `left` / `right`: 고리 중심 기준 도구 좌표로 `(0.09, -0.065, ∓0.11)` m.
  고리 중심에서 약 15.6 cm 떨어진 측면 후보다. 시선은 고리 중심에서
  `(-0.055, -0.008, 0)` m인 지점을 향한다. 좌우 명칭은 이 좌표 정의를 따른다.
- 후보 영상은 960×720, 수평 화각 60°, near clipping 1 cm다.
  실제 렌즈의 최소 초점 거리, 조명, 마운트/하우징 충돌은 아직 검증하지 않았다.
- 카메라는 관절 FK와 고정 외부 파라미터로만 이동한다. 목표를 따라다니는 카메라가 아니다.
- 왼쪽 seed 영상의 수동 ROI는 `(194, 197, 80, 86)`이다. 이 값은 현재 Tomato_05
  배치/경로/카메라에만 맞는다. 다른 토마토에는 영상에서 ROI를 다시 지정해야 한다.

고정 경로의 196번째 제어 단계에서 ROI 안의 과실과 꽃받침 특징점을 선택한다.
처음 식물이 정지해 있다는 가정 아래 여러 RGB 프레임과 관절로 계산한 카메라 이동을
이용해 특징점 위치를 추정한다. Depth 센서나 렌더러 depth를 읽지 않는다.
3 cm 이상의 카메라 이동과 시차/재투영 검사에 통과해야 모델을 사용한다.

LK 영상 추적의 이동량에서 관절/카메라 모델이 예측한 이동량을 빼고, 최근 6프레임의
잔차를 합한다. 4 px 초과가 3회 지속되면 `motion_or_model_mismatch`로 멈춘다.
특징점 부족·가림·불안정한 모델도 중단 사유다. 이 판단은 **식물 움직임 또는 모델 오류**를
뜻하며 접촉 힘, 밀린 줄기의 정체, 고리걸기 성공을 알아내지는 못한다.

정지 후 실제 관절 위치를 6제어 단계 유지하고, 최근 121개의 실행된 관절 명령을
역순으로 반속 재생한 뒤 1초 유지한다. 후퇴 경로의 안전성을 보장하는 제어기는 아니며,
이번 배치에서 물리 결과를 별도로 확인한다. 현재 후퇴 중에는 추가 영상 기반 재계획을 하지 않는다.

## 입력 분리와 한계

`rgb_guard.py`는 RGB, ROI, 카메라 보정값과 관절에서 계산한 카메라 pose만 받는다.
`observations.json`에는 영상 시각과 관절/판단을 저장한다. `evaluation_only.json`과
`contacts_evaluation_only.json`의 위치·접촉·절단 정보는 명령을 실행한 뒤 별도 평가에만
기록하며 정지/후퇴 조건으로 읽지 않는다. 기존 `MotionTrial.step`의 접촉 기반 가드는 호출하지 않는다.

초기 자세/송이 배치는 기존 설정을 사용한다. 접근 명령은 과거 시뮬레이터 형상을 이용해
계획한 궤적의 고정 기록(`configs/tomato05_rgb_reference.npz`)이다. 따라서 **전체 접근까지
RGB로 생성했다는 의미는 아니다.** 이번 검증 범위는 해당 접근의 근접 감시와 후퇴다.

단안 RGB의 모호성, 잎/고리 가림, 초점과 모션 블러, 시간 동기화, 관절/카메라 보정 오차,
초기부터 움직이는 식물은 남은 검증 항목이다. 특권 상태를 정책에 넣지 않았다는 것만으로
sim-to-real이 입증되지는 않는다. 다음 단계는 센서 지연/보정 오차/배치 변화에 대한 검증과
후퇴 후 재관찰·접근 방향 보정이며, 이 신호를 보상/관측으로 사용하는 RL은 그 이후에 평가한다.

## 오프라인 재생과 검사

특징점별 계산까지 설명하는 영상은 다음처럼 저장한다. 실행 당시의 무손실 RGB와
특징점/예측 이동을 기록하므로, 압축 영상에서 추적을 다시 수행하지 않는다.

```bash
./nvidia-sim/run_rgb_guard.sh --headless --rgb-analysis
# 위 실행이 만든 날짜 폴더를 RUN에 지정
/root/isaaclab_env/bin/python nvidia-sim/rl/rgb_visualize.py RUN
```

`rgb_decision_2x.mp4`는 전체 2배속, `rgb_decision_explained.mp4`는 판단 부근을
0.25배속으로 재생하고 연속 초과 1/2/3회에서 설명용 정지 화면을 넣는다. 물리 계산은 같다.
노란색은 실제 관측 이동, 청록색은 카메라 이동으로 예측한 이동, 분홍색은 둘의 차이다.
그래프와 연속 초과 횟수는 실제 온라인 로그이며 특징점별 오차로 다시 검산한다.
후퇴 중에는 새 추적점을 표시하지 않고 확대 영역만 판단 순간으로 고정해 명시한다.
`rgb_analysis.json`, `left_raw_2x.mkv`, `visualization_report.json`이 원본/검증 기록이다.

```bash
/root/isaaclab_env/bin/python nvidia-sim/rl/rgb_replay.py RUN/compare_v2 \
  --camera left --roi 194 197 80 86 --output RUN/left_replay
PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 /root/isaaclab_env/bin/python -m pytest -q nvidia-sim/rl
```

오프라인 재생은 RGB mp4와 관절 로그/보정값만 읽는다. 압축 영상 재생 결과와 실제
닫힌 루프 제어 결과는 구분해야 한다. 영상에 표시한 감지 사유는 후퇴 동안 마지막 판단을 유지한다.

## 2026-09-19 과거 실행 결과 — 추적 대상 불일치

출력 폴더: `runs/20260919_225748_rgb_camera_guard_tomato05/`.
`camera_comparison_2x.mp4`는 기존/좌/우 시야 비교,
`baseline_vs_guard_2x.mp4`는 왼쪽 카메라의 접근 유지/정지·후퇴 비교다.
비교군은 기록된 접근의 557단계(삽입 구간까지)와 1초 유지이며, 이전 전체 수확 실행과는
관찰 구간이 다르다. 비교 영상은 짧은 쪽이 끝나면 마지막 프레임을 유지한다.

| 항목 | 접근 유지 | RGB 정지·후퇴 |
|---|---:|---:|
| Tomato_05 최대 변위 | 26.2 mm | 9.1 mm |
| 주줄기 세그먼트 최대 변위 | 42.6 mm | 15.3 mm |
| 열매 파손 | 없음 | 없음 |

실제 닫힌 루프에서 최초 접촉은 409단계, RGB 정지 판단은 416단계였다(약 0.117초 후).
판단 시 목표 변위는 약 3.1 mm였지만 관성과 후퇴 과도응답 때문에 최대 변위는 9.1 mm였다.
후퇴 및 유지 종료 시 목표 변위는 약 1.6 mm였다. 위 수치는 별도 평가용 상태로 계산했다.
정지 전 두 실행의 명령/관절/목표 변위가 같음을 확인했다.

상세 수치는 [검증 기록](validation/rgb_guard_tomato05.json)에 저장했다. 이 결과는
현재 배치의 한 사례이며 여러 배치/토마토에 대한 성공률을 뜻하지 않는다. 고리걸기/수확
성공은 판정하지 않았다(`harvest_success: null`). 합성 영상의 카메라 이동·대상 이동·가림·시차 부족
검사를 포함하여 저장소 테스트 25개가 통과했다.

## 대상 수정 후 실행

`runs/20260919_235104_rgb_target_identity_fix/corrected_target`에서 수정한 ROI를 실제 실행했다.
288단계(4.817초)에 유효 특징점이 7개가 되어 최소 8개 기준으로 중단·후퇴했다.
접촉 이벤트는 0개다. 이는 밀림 감지 성공이 아닌 추적 불확실성 중단이다.
[대상 감사 기록](validation/rgb_target_identity_audit.json)에 초기 ID/ROI 확인과 재실행 결과를 남겼다.
