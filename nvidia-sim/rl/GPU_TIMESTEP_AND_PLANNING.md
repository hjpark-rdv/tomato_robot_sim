# GPU 물리 주기와 CPU 경로 병렬화

## 실행

```bash
# 기존 물리 조건 유지. 경로 계산만 최대 8개 CPU 프로세스로 미리 처리.
./nvidia-sim/run_gpu_candidate_dataset.sh \
  --num-envs 4 --candidates 32 --schedule continuous --planning-workers 8

# 기존 순차 경로 계산과 비교
./nvidia-sim/run_gpu_candidate_dataset.sh \
  --num-envs 4 --candidates 32 --schedule continuous --planning-workers 0

# 물리 주기 비교용. 기본값은 여전히 960Hz이며 낮은 주파수는 실험용.
./nvidia-sim/run_gpu_candidate_dataset.sh \
  --num-envs 1 --candidates 1 --physics-hz 480
```

`--physics-hz`는 60/120/240/480/720/960을 받는다. `decimation=Hz/60`으로
함께 설정해서 로봇 명령과 판정/기록은 60Hz로 유지한다. 솔버 반복 수,
강성/감쇠/질량/마찰/파손 임계값, 모션 속도와 경로는 바꾸지 않는다.
물리 스텝 내부의 접촉 감시 빈도는 물리 주파수에 따라 달라진다.

## CPU 경로 준비

- 기본 최대 8개 CPU worker. 대기 후보 수로 제한하며 후보가 하나면 순차 계산한다.
- Isaac Sim은 한 프로세스만 실행한다. CPU worker에는 현재 USD에서 구성한
  실제 FCL 충돌 도형, 제외할 충돌 쌍, FK/IK 모델, 초기 관절/타겟 위치를 전달한다.
- 동일한 `dataset_motion.plan()`을 실행한다. IK, 모든 경로 샘플의 자기충돌 검사,
  속도/관절 한계 검사를 생략하지 않는다.
- 후보 순서는 그대로다. 계산이 빨리 끝난 후보부터 물리 시험 순서를 바꾸지 않는다.
- 전체 대기 후보의 경로를 백그라운드에서 미리 계산하므로 물리 실행과 겹칠 수 있다.
  해당 후보의 경로가 아직 없으면 기다린다. 최초 환경 채우기에도 대기 시간이 있다.
- 슬롯을 리셋한 뒤 초기 관절/타겟 위치를 준비 당시 값과 비교한다. 다르면 중단한다.
- `planning_날짜시간/`에는 모델, 계획 결과, CPU worker 로그/진행/요약을 저장한다.
  재시작 시 새 경로 준비 디렉터리를 사용하며, 기존 실행의 소스/설정 검사를 유지한다.
- `DATASET READY`는 경로 준비 완료를 뜻한다. 로봇 spawn이나 물리 진행 스텝이 아니다.
- `phase_timings.planning_s`는 메인 스레드가 기다린 시간이다. 후보별
  `planning_compute_s`는 worker 내부의 실제 계산 시간, `planning_wait_s`는 대기 시간이다.
  병렬 작업 시간을 모두 더하면 실제 경과 시간보다 클 수 있다.

## 재현용 비교 도구

저장된 후보의 `candidate.json`, `planned_commands.npy`가 있는 경로를 사용한다.

```bash
/root/isaaclab_env/bin/python nvidia-sim/rl/gpu_timestep_benchmark.py \
  --fixture nvidia-sim/rl/runs/실행폴더/results/candidate_00003

# 실제 장면에서 내보낸 모델로 경로 계산 비교. Isaac을 실행하지 않는다.
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
/root/isaaclab_env/bin/python nvidia-sim/rl/gpu_planning_benchmark.py \
  --model nvidia-sim/rl/runs/실행폴더/planning_날짜시간/model.pkl \
  --output nvidia-sim/rl/runs/새로운_경로계산_비교폴더 \
  --candidates 32 --workers 4 8
```

주파수 비교는 각 설정을 하나씩 실행해 GPU 경합을 피한다. 초기화와 동작 실행 시간을
분리하고, 조기 종료나 경로/판정 차이가 있으면 유효한 speedup으로 채택하지 않는다.
기본 비교 허용치는 위치 관련 지표 1mm, 로봇 관절 0.005rad, 종료 시점 1제어 스텝이다.
이것은 현재 960Hz 구현과의 회귀 검사이며 실물 정확도 인증이 아니다.

## 2026-09-21 CPU 측정 결과

실제 장면에서 추출한 로봇 충돌 도형 44개 / 검사 쌍 228개를 사용했다.
64개 서로 다른 후보의 전체 경로를 계산·검사했으며, 모든 후보의 관절 명령,
waypoint, 방향, quaternion과 preflight 판정이 순차 방식과 정확히 일치했다.

| 방식 | 64개 후보 경로 준비 | 순차 대비 |
|---|---:|---:|
| 순차 | 86.14초 | 1.00× |
| CPU worker 4개 | 23.86초 | 3.61× |
| CPU worker 8개 | 13.57초 | 6.35× |

프로세스 시작·결과 전달·종료 비용을 포함한 단일 측정이다. 전체 데이터셋이
6.35배 빨라진다는 의미는 아니다. 물리 계산 시간은 별도다.

추가로 4개 물리 환경 / 8개 서로 다른 후보 / 후보당 8개 제어 스텝의 통합 비교에서
전체 계획 명령, 실행한 구간의 모든 trace, reset 검사, 결과가 정확히 일치했다.
이 짧은 구간에는 로봇–식물 접촉이 없었으며 접촉 로그도 양쪽 모두 비어 있었다.
전체 수확 성공 검증으로 해석하지 않는다. `incomplete` 라벨을 유지했다.
메인 실행기의 경로 대기는 12.61초에서 3.24초로 감소했다. 남은 경로를
물리 실행과 겹쳐서 준비하므로 worker 전체 실행 시간과 대기 시간이 다르다.

## 주파수 해석 주의

낮은 주파수에서 일찍 변위 한도를 넘으면 수행한 물리 시간 자체가 짧다.
예를 들어 60Hz의 0.2초 실행과 960Hz의 156초 실행을 나누어 780배 빨라졌다고
해석하면 안 된다. 전자는 시뮬레이션 0.067초에 이미 중단됐고 후자는 4.333초를 수행했다.
480/720Hz는 이 시험에서 동일한 260개 제어 스텝을 수행했으나, 위치 지표가 달라졌다.
회귀 검사를 통과하지 못한 조건은 `accepted_speedup=null`로 기록한다.

960Hz 역시 실물 정답으로 검증된 값은 아니다. 이번 시험은 기존 데이터와의
일관성을 검사한 것이다. 전체 성공 pose 영역이나 sim-to-real 정확도를 평가하지 않았다.
주파수를 더 낮추려면 탄성 관절 모델과 솔버의 시간 간격 민감도를 별도로 다뤄야 한다.
이번 변경에서는 해당 물성이나 구조를 바꾸지 않았다.

## 2026-09-21 물리 주기 측정 결과

동일한 저장 명령 `candidate_00003`을 1개 / 4개 환경에서 각각 실행했다.
전체 12개 설정 실행이 완료됐으며 native PhysX 오류는 없었다.
4개 환경에서는 동일 명령을 복제해 주파수 영향만 비교했다. 서로 다른 4개 pose의
처리량 또는 전체 수확 성공률을 측정한 것은 아니다.

| 물리 주파수 | 1환경 동작 계산 | 4환경 동작 계산 | 진행한 시뮬레이션 시간 | 기존 960Hz와 비교 |
|---|---:|---:|---:|---|
| 960Hz | 156.25초 | 168.69초 | 4.333초 | 기준 |
| 720Hz | 117.84초 | 128.39초 | 4.333초 | 위치 지표 1mm 기준 초과 |
| 480Hz | 79.18초 | 87.50초 | 4.333초 | 위치 지표 1mm 기준 초과 |
| 240Hz | 16.28초 | 18.62초 | 1.750초 | 로봇 접촉 이전 변위 한도 초과 |
| 120Hz | 4.92초 | 6.20초 | 1.017초 | 로봇 접촉 이전 변위 한도 초과 |
| 60Hz | 0.19초 | 0.24초 | 0.067초 | 주줄기 변위 약 198mm, 조기 종료 |

시간은 초기화를 제외했다. 모든 trial의 최종 라벨은 `excessive_displacement`지만,
동일 라벨만으로 동일한 물리 동작이라고 판단하지 않았다. 60/120/240Hz에는
종료 시까지 로봇의 첫 접촉도 없었다. 960Hz는 접촉 이후 변위 한도에서 종료됐다.

720Hz의 공통 경로 구간에서 고리 간격 차이는 최대 1.49mm, 주줄기 변위 지표
차이는 1.33mm였다. 종료 시 각 줄기 바디 위치를 직접 비교하면 최대 2.31mm,
과실 위치는 최대 2.08mm 차이가 났다. 480Hz는 고리 간격 차이가 최대 2.74mm였다.
이는 1환경과 4환경 모두에서 같은 수준으로 재현됐다.

따라서 물리 기본값은 **960Hz 유지**. 480/720Hz가 같은 시간 구간을 더 빨리
계산하는 것은 확인했지만, 기존 결과를 유지하는 대체 설정으로 채택하지 않는다.
64개 CPU 경로 측정의 6.35배 개선과 물리 계산 개선을 혼동하지 않아야 한다.
