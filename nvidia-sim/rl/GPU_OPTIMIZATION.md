# GPU 실행 개선 — 2026-09-21

물리 모델·960 Hz·PGS 64/4회·접촉/파단 기준을 유지하고 실행기와 명령 전달을 개선했다.
기존 CPU 실행기는 수정하지 않았다.

## 실행

```bash
./nvidia-sim/run_gpu_candidate_dataset.sh \
  --num-envs 256 --candidates 1000 --schedule continuous
```

명령 일괄 전송은 기본값 `--command-uploads batched`이다.
완료 슬롯을 즉시 재사용하려면 `--schedule continuous`를 지정한다.
기존 대기 방식은 `--schedule batch`, 기존 명령 전달은 `--command-uploads legacy`로
비교할 수 있다. 같은 실행 폴더에서 옵션을 바꿔 재개할 수는 없다.

## 변경 내용

- **완료 슬롯 재사용:** 전체 배치가 끝날 때까지 기다리지 않고 해당 슬롯의 로봇·식물·
  열매·파단 조인트를 복원한 뒤 다음 후보를 배정한다. 복원 상태가 초기 기준과
  다르면 중단한다. 초기 RGB-D는 동일한 초기 상태의 공통 관측을 계속 사용한다.
- **계획 기준 슬롯:** 실행 중인 env_0의 변형 상태를 사용하지 않고, 방금 복원한
  슬롯에서 GT와 시작 관절값을 읽어 기존 IK/FCL 계획을 수행한다.
- **관절 명령 묶음 전송:** implicit actuator 계산과 토크 추정 버퍼를 유지한다.
  모든 제어 계산이 끝난 후 위치·속도·effort 명령을 articulation 종류별로 묶어
  PhysX에 전달한다. 환경마다 명령을 쓰면서 공유 조회 캐시를 무효화하고 전체 상태를
  다시 가져오던 반복 작업을 줄인다. 외력/explicit actuator 미지원 시 중단하는
  기존 검사는 유지한다.

## 짧은 구간 처리량 실측

동일한 저장 명령의 처음 32 control steps(512 physics steps, 시뮬레이션 0.533초)를
각 환경에서 실행했다. 초기화 시간은 아래 표에서 제외했다. 모든 후보는 의도적으로
`incomplete`이며, 아래 값은 전체 후보의 수확 판정 처리량이 아니다.

| 환경 수 | 명령 전달 | 실행 시간 | 기존 32환경 대비 합산 스텝 처리량 |
|---:|---|---:|---:|
| 32 | 기존 | 39.34초 | 1.00배 |
| 128 | 기존 | 64.38초 | 2.44배 |
| 256 | 기존 | 92.59초 | 3.40배 |
| 256 | 일괄 전송 | 90.61초 | 3.47배 |

256환경의 입력 전달 구간은 10.23초 → 7.26초로 약 29% 감소했다.
전체 시간 감소는 약 2%로 작았고, 단일 측정이라 이를 보장된 개선률로 해석하지 않는다.
현재 가장 큰 실측 이득은 큰 배치에서 얻었다. 연속 배정의 전체 데이터셋 시간 단축률은
아직 측정하지 않았다. 이번 동일 길이의 짧은 후보 검사로 배치 대기 제거 효과를
숫자로 주장하지 않는다.

**1,000개 전체 후보의 완료 시간이나 1시간 내 완료를 실측한 결과는 아니다.**
주요 GPU 관절 커널 비용은 남아 있다. 모델/솔버 정밀도를 낮추는 변경은 적용하지 않았다.

## 검증 범위

- 128/256환경의 짧은 재생 상태와 결과가 32환경 기준과 일치했다.
- 256환경의 기존/일괄 전송 비교에서 모든 환경의 기록된 궤적·결과가 일치했다.
- 2환경에서 후보 4개를 batch/continuous 방식으로 각각 실행했다. 명령 배열과
  4 control steps의 관절·변위·고리 간격이 정확히 같고 reset 검사도 통과했다.
  모두 `incomplete`로 보존했으며 성공/실패 학습 데이터로 분류하지 않았다.
- 별도의 2환경 실험에서 한 슬롯을 9번 리셋해도 옆 슬롯의 전체 260스텝 궤적이
  기존 종료 사례와 일치했다.
- 새 명령 전달을 사용하는 32환경에서는 env_0을 8번 리셋하며 접촉 구간까지
  260 control steps를 재생했다. 나머지 31환경의 모든 최종 상태 필드
  (로봇/식물 관절 위치·속도, 몸체/과실 상태, preload, stiffness, damping)가
  기준과 정확히 같았다. 각 환경의 접촉 로그 1,336건도 환경 경로 번호를 제외하면
  정확히 같았다. 즉시 reset 검사와 native 파단/복원 검사도 통과했다.
- 이 32환경 진단은 `max-control-steps=260`이므로 결과 라벨이 `incomplete`이다.
  원래 기준의 과도한 변위 종료와 같은 스텝까지 상태/접촉을 비교한 것이며,
  전체 후보 판정이나 다양한 고리걸기 성공을 검증했다고 주장하지 않는다.

이는 GPU 구현 전후의 재현성 검사다. CPU TGS와 GPU PGS의 동등성이나 현실 식물의
탄성 보정 결과를 의미하지 않는다.
