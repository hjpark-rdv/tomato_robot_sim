# 원본을 유지하는 별도 경량 식물 모델

추가된 `ultralight` 모델과 단일 환경 CPU 실시간 실행은
[ULTRALIGHT_PLANT.md](ULTRALIGHT_PLANT.md)를 참고한다. 아래 내용은 기존 `light` 모델이다.

원본 USD를 수정하거나 교체하지 않는다. 기존 실행의 기본값은 `--plant-resolution full`이다.
`--plant-resolution light`를 지정하면 동일 USD에서 별도의 경량 물리 관절 구조를 구성한다.
물리 주파수와 정밀도 프리셋은 별도 옵션이며 기본 contact120을 유지한다.

**현재 light 기본값은 주줄기의 잎·잘린 가지 충돌을 무시한다.** 원본 `full`에는
적용하지 않는다. `--main-appendage-collisions keep`을 light와 함께 지정하면
이전 경량 모델(잎 충돌 유지)을 비교용으로 실행할 수 있다.

## 현재 기본값(ignore)의 변경과 속도

실제 활성 식물 충돌체는 376 → 90개다. 제거한 286개는 주줄기의 잎·잘린 가지
convex mesh다. 남은 것은 줄기 capsule 68개, 열매 sphere 11개, 열매 쪽 꼭지
capsule 11개다. 주줄기와 송이 캡슐의 형상·충돌 필터, 관절 구성, 질량은
이전 `light keep`과 같고, 초기 카메라 depth도 정확히 일치했다.
RGB는 평균 절대 차이 0.057/255였으며 원본 잎·가지가 그대로 보이는 것을 확인했다.

동일 4환경, 후보 0·1·5·49, 120Hz/60Hz, 각 후보 600제어 스텝(10초), GUI 없이
순차 측정했다. 잘라 실행한 후보는 모두 `incomplete`로 보존했다.

| 항목 | 원본 full | 기존 light keep | 현재 light ignore |
|---|---:|---:|---:|
| 초기화 | 17.76초 | 17.67초 | 9.85초 |
| 계획·실행·판정·저장 | 76.03초 | 68.55초 | 66.08초 |
| 위 실행 중 물리 스텝 처리 | 45.88초 | 38.24초 | 36.19초 |
| 식물 충돌체 | 376 | 376 | 90 |
| 식물 자유도 | 234 | 165 | 165 |

원본 대비 실행 약 13.1%, 초기화 약 44.5% 단축이다. 이번 잎 충돌 제거만의
추가 효과는 기존 light 대비 실행 약 3.6%, 초기화 약 44.3%다.
충돌체 개수 감소가 실행 시간에 그대로 비례하지 않는다. 반복 측정 평균이나
64/256환경 성능은 아니다. 이 버전에서도 full의 4후보 trace는 이전 원본과 정확히 일치했다.

최신 실행 폴더: `runs/20260921_main_appendages_comparison`.

현재 ignore 설정으로 5번·49번을 끝까지 실행했다. 둘 다 과도 변위로 중단했으며
최대 겹침은 각각 0.222/0.317mm로 0.5mm 제외 기준 이내였다. 제외한 잎/잘린 가지의
접촉 이벤트는 0개였다. 완전 수확 성공 검증으로 해석하지 않는다.

정지 안정성, 0.2N 하중 후 휘어짐·복원, 6N 하중의 목표 꼭지 파손, 리셋,
미리 끼운 고리의 네 방향 접촉 유지 검사도 통과했다. 최대 목표 변위 24.67mm,
복원 후 잔류 변위 1.51mm, 연결부 최대 간격 0.022mm였다.
관련 자동 테스트 39개 통과. 검증 요약: `validation/main_appendage_light.json`.

## 실행

```bash
# 원본 모델: 기존 명령과 동일
./nvidia-sim/run_gpu_candidate_dataset.sh \
  --plant-resolution full --physics-preset contact120 --trajectory-mode staged6d \
  --num-envs 4 --candidates 64 --candidate-indices 0,1,5,49 --planning-workers 4

# 별도 경량 모델: 같은 후보로 비교
./nvidia-sim/run_gpu_candidate_dataset.sh \
  --plant-resolution light --physics-preset contact120 --trajectory-mode staged6d \
  --num-envs 4 --candidates 64 --candidate-indices 0,1,5,49 --planning-workers 4

# 49번만 화면으로 확인
DISPLAY=:0 ./nvidia-sim/run_gpu_candidate_dataset.sh \
  --plant-resolution light --physics-preset contact120 --trajectory-mode staged6d \
  --num-envs 1 --candidates 64 --candidate-indices 49 --planning-workers 1 \
  --view-grid --view-fps 10 --keep-open
```

경량 모델 자동 저장 폴더에는 `_light`를 붙인다. 명시적인 `--run-dir`은 지정한 경로를 쓴다.
config, backend, 각 후보 JSON/CSV, 최종 summary에 모델을 기록한다.
잎 충돌 정책 `main_appendage_collisions`도 별도로 기록하며 다른 정책으로 resume하거나
원본 영상과의 비교를 통과시키지 않는다. 정책이 없는 이전 데이터는 `keep`으로 해석한다.
두 모델의 결과를 같은 폴더에 이어 쓰는 것은 거부한다. 기존 config에 옵션이 없으면
원본으로 해석한다. 대표 영상 재실행에도 원본 실행의 모델 옵션을 전달한다.
기존 소스 해시 검사도 유지하므로, 코드가 바뀌기 전에 만든 실행 폴더를 이어 쓰려면
당시 코드가 필요하다. 이번 버전의 시험은 새 폴더에서 시작한다.

## 경량화 범위

- 열매 11개, 열매 무게, 꼭지 파손 연결, 주줄기와 송이 가지의 캡슐 충돌체,
  원본 시각 메시와 남아 있는 물체 사이의 충돌 필터를 유지한다.
- 주줄기에 붙은 잎·잘린 가지의 convex 충돌체 286개는 light 기본값에서 생성하지 않는다.
  원본 시각 메시는 주줄기를 따라 움직인다. 주줄기 몸통과 `TRUSS_` 송이 가지는 제외 대상이 아니다.
  잎을 누르거나 걸리는 실패는 이 설정에서 재현되지 않는다.
- 목표 중심에서 70mm 안쪽 줄기 구간과 목표 proximal pedicel 전체는 원래 관절을 유지한다.
  목표가 바뀌면 보호 영역도 새 목표 기준으로 계산한다. 보호 영역은 초기 위치 기준이다.
- 먼 구간은 연속된 관절 약 4개당 1개만 휘도록 남기고, 나머지는 고정 연결로 바꾼다.
  고정 연결은 부모와 함께 움직이며, 식물을 월드에 추가 고정하지 않는다.
- 남긴 먼 구간의 강성·감쇠에는 `남긴 관절 수 / 원래 관절 수`를 곱한다.
  일정한 굽힘 모멘트에서 작은 각도의 직렬 유연성을 근사하는 값이다.
  힘의 작용 위치가 달라질 때의 변형, 진동 모드와 큰 변형까지 동일하지는 않다.
- 중력 초기 하중은 경량 구조의 Jacobian으로 다시 계산한다. 움직임을 인위적으로
  추적시키지 않으며 주줄기·송이 접촉과 0.5mm 관통 제외 검사를 유지한다.

Tomato_05의 식물 자유도는 234 → 165다. 주줄기 탄성 관절은 15 → 5개,
송이 탄성 관절은 63 → 50개다. 열매는 원래 sphere, 가지·꼭지는 capsule로 단순화돼 있다.
몸체와 중요 부위 충돌체를 유지하므로 자유도 감소율이 실행 시간 감소율과 같지는 않다.
생성된 `plant_model.json`에
남긴 관절 목록, 강성 계수, 원본 형상·질량 해시와 실제 자유도를 기록한다.
`collision_inventory`에는 실제 활성 CollisionAPI를 조사한 부위별/형상별 개수를 기록한다.

경량 모델은 빠른 후보 탐색을 위한 근사 모델이다. 좋은 후보와 경계 사례는
`full`에서 재검증한다. 일부 탈락 후보도 원본에서 확인해 경량 모델 때문에 좋은
경로를 버리는지 검사한다. 두 모델의 성공률을 같은 물리 조건의 데이터로 합치지 않는다.

## 이전 경량 모델(잎 충돌 keep)의 시험 기록

아래 수치는 `--plant-resolution light --main-appendage-collisions keep`에 해당한다.
현재 기본값인 `ignore`의 검증 수치와 혼동하지 않는다.

원본 `full`의 4환경 시험에서 후보 0·1·5·49의 처음 600제어 스텝(각 10초)은
기존 `runs/20260921_contact_fix/regression4`의 trace와 전체 값이 정확히 일치했다.
원본 모델의 움직임을 바꾸지 않은 상태에서 별도 옵션을 추가했음을 확인했다.

경량 모델에서 같은 계획 관절 명령으로 4후보를 끝까지 실행했다.

| 후보 | 원본 판정 | 경량 판정 |
|---|---|---|
| 0 | miss | miss |
| 1 | excessive_displacement | excessive_displacement |
| 5 | miss, 중심 진입 0.833초 | excessive_displacement, 중심 진입 없음 |
| 49 | excessive_displacement | excessive_displacement |

경량 시험의 0.5mm 관통 선별 기준 초과는 0개이며 완전 걸림 성공도 0개다.
5번처럼 결과가 달라질 수 있어 원본의 대체 정답 모델로 취급하지 않는다.
실행 구간은 257.4초였지만 종료 시점과 접촉 상태가 달라지므로, 원본과의 속도
비교에는 별도로 실행한 동일 10초 분량 벤치마크를 사용한다.

원본 실행 결과는 그대로 남겨 두었다. 경량 접촉 실행:
`runs/20260921_light_plant_4env`.
동일 길이 비교 및 물리 반응 검사: `runs/20260921_plant_model_comparison`.

## 이전 keep 모델의 동일 길이 속도 비교

RTX 3090 Ti, 동일 4환경/후보 0·1·5·49, 120Hz 물리/60Hz 제어, GUI 없이 순차 측정했다.
각 후보를 600제어 스텝(10초)까지 실행했다. 두 시험 모두 1,200물리 스텝이며
속도 측정용으로 자른 후보는 모두 `incomplete`다. 성공률 데이터로 사용하지 않는다.

| 항목 | 원본 full | 경량 light |
|---|---:|---:|
| 초기화 | 18.06초 | 17.77초 |
| 계획·실행·판정·저장 | 75.43초 | 66.86초 |
| 위 실행 중 물리 스텝 처리 | 45.76초 | 38.23초 |
| 식물 자유도 | 234 | 165 |
| 식물 articulation 몸체 | 79 | 79 |

실행 구간 약 11.4%, 물리 스텝 처리 약 16.5% 단축이다. 반복 측정 평균이나
64/256환경 처리량은 아니다. 충돌체·몸체를 유지하는 보수적 모델이므로 속도 개선에 한계가 있다.
두 모델의 줄기 형상·질량 해시와 실제 articulation 총질량은 정확히 같았다.
124개 캡슐/구 충돌체 경로·반경·활성 여부·충돌 필터도 일치했다
(native 좌표로 다시 표현한 끝점의 최대 차이 약 1.4nm).

## 이전 keep 모델의 기본 물리 반응

기존 mechanics fixture의 정지 안정성, 힘을 가한 뒤 휘어짐·복원, 꼭지 파손,
파손 후 리셋, 미리 끼운 고리 접촉 유지 검사를 모두 통과했다.
0.2N 하중 시험의 목표 최대 변위는 24.67mm, 복원 후 잔류 변위는 1.51mm였고,
열매 연결부 최대 간격은 0.022mm였다. 미리 끼운 고리는 네 방향 모두 접촉을 유지했다.
이 검사는 로봇이 실제로 진입해서 수확에 성공했다는 뜻은 아니다.

검증 요약: `validation/light_plant.json`. 관련 자동 테스트 37개 통과.
