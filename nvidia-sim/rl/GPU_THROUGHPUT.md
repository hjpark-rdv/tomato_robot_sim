# GPU 후보 탐색 처리량 실측

```bash
./nvidia-sim/run_gpu_throughput_benchmark.sh
```

기본값은 화면 없는 GPU 32 / 64 / 128환경을 **순차적으로** 실행하고,
각 설정에서 같은 seed와 동일한 후보 128개를 끝까지 처리한다.
실험 프로세스를 동시에 띄워 서로 GPU를 점유하게 하지 않는다.
로봇 속도, 960 Hz, solver, 접촉/파단 조건은 바꾸지 않는다.
시작 시 출력하는 datetime 실행 폴더에 결과를 저장한다.

- `benchmark.md`, `benchmark.csv`, `benchmark.json`: 설정별 처리량·시작 시간·비교 결과.
- `env_0032/`, `env_0064/`, `env_0128/`: 원래 RGB-D·후보/명령·trace·접촉 로그.
- `env_XXXX_comparison.json`: 기준 실행과 후보별 명령·종료 분류·첫 접촉·물리 trace 비교.
- `env_XXXX.console.log`: 해당 설정의 실행 로그.

미완료 후보는 완료 처리량에서 제외한다. 같은 성공/실패 분류라도 명령이 다르거나,
trace의 위치/관절 차이가 기존 GPU 재생 비교 기준(0.1 mm / 0.0001 rad)을 넘으면
비교에 실패한 것으로 기록하고 추천에서 제외한다. CPU TGS와의 동등성은 별개다.

`candidates_per_minute`는 계획 실패를 포함한 전체 동일 작업량의 판정 속도이고,
`completed_physics_per_minute`는 실제 물리 동작을 끝낸 후보의 처리량이다.
반복 실행 시의 효율은 초기화를 제외한 전자를 기준으로 비교하고,
Kit 실행과 초기화까지 포함한 처리량도 별도로 저장한다.
모든 설정의 측정이 끝나기 전에는 최적 환경 수를 출력하지 않는다.
한 번의 고정 작업량 측정이므로 모든 송이/각도에서의 절대 최적값은 아니다.

`phase_timings`는 batch reset, IK/FCL 계획, 실행 상태/성공 판정, 결과 저장 시간을 기록한다.
`rollout_step_timings`는 실제 후보 실행 구간의 입력 전송, 물리 스텝, 상태 갱신 시간이다.
물리 스텝 시간에는 native GPU 계산뿐 아니라 프레임워크의 동기화/쓰기 비용도 포함된다.
`active_env_step_fraction`은 할당된 환경×물리 스텝 중 실제 진행 중이던 후보의 비율이다.
먼저 끝난 환경이 느린 후보를 기다리는 batch barrier 비용을 드러낸다.

중단된 실험은 다음처럼 재개한다. 이미 끝난 설정은 재사용하고,
중간에 멈춘 설정은 기록을 보관한 뒤 처음부터 다시 측정한다.
실행 중인 폴더를 다른 프로세스가 동시에 재개하려 하면 잠금으로 차단한다.

```bash
./nvidia-sim/run_gpu_throughput_benchmark.sh --run-dir <실험폴더> --resume
```

실행 중에는 `env_XXXX/progress.json`에서 완료 후보 수와 단계별 소요 시간을
확인할 수 있다. `benchmark.md`는 환경 수 하나의 측정이 끝날 때마다 갱신하며,
전체 비교가 끝나면 검증을 통과한 설정 중 가장 빠른 환경 수를 기록한다.
현재 배치에서 일찍 끝난 후보의 속도로 전체 완료 시간을 판단하지 않는다.
긴 후보까지 끝내는 실측이므로 여러 시간 걸릴 수 있다.

후보 수는 가장 큰 병렬 환경 수 이상이어야 한다. 일부 슬롯만 채우고 큰 병렬 환경의
성능인 것처럼 비교하지 않는다. 1,000개 예상 시간은 실측 처리량의 선형 추정이며
전체 1,000개 완주 실측값이 아니다. 최종 추천 전에 결과 일치 항목을 확인한다.
