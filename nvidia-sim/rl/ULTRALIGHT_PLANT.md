# 초경량 모델과 단일 환경 실시간 실행

2026-09-21. 기존 작업 커밋: `a270554`.
`full`과 `light`를 유지하고 `--plant-resolution ultralight`를 추가했다.
기본 모델은 여전히 `full`, 기본 물리 장치는 `gpu`다.

## 먼저 실행하기

실시간에 가까운 **단일 환경 CPU 물리 + GPU 화면 표시**:

```bash
cd /root/farmily_tomato
DISPLAY=:0 ./nvidia-sim/run_gpu_candidate_dataset.sh \
  --physics-device cpu --plant-resolution ultralight \
  --physics-preset contact120 --trajectory-mode staged6d \
  --num-envs 1 --candidates 64 --candidate-indices 49 \
  --planning-workers 1 --view-grid --view-fps 10 --keep-open
```

기존 실행기 이름을 유지했지만 `--physics-device cpu`는 실제 CPU PhysX를 사용한다.
화면과 RGB-D 렌더링은 GPU를 사용한다. `64`는 후보 생성 풀 크기이고 실제로는
49번 하나만 실행한다. 다른 후보는 `--candidate-indices`로 선택한다.
CPU 모드는 현재 환경 1개만 지원한다. 여러 환경은 기존 GPU 모드를 사용한다.
`--keep-open`은 시험 후 창을 유지한다. 단일 환경은 처음부터 목표 토마토를 중심으로
송이와 고리가 보이는 가까운 사선 구도로 시작한다. `Overview`는 전체 화면으로 돌아가며,
환경 행을 누르면 토마토 구도를 다시 잡는다. 다중 환경은 전체 격자로 시작한다.
이 구도는 화면용이며 데이터셋 RGB-D 카메라의 위치는 바꾸지 않는다.

## 무엇을 줄였나

Tomato_05 기준, 식물 articulation만 집계한 값이다. 로봇과 별도 열매 강체는 제외한다.

| 항목 | full | light | ultralight |
|---|---:|---:|---:|
| 식물 강체 | 79 | 79 | 33 |
| 자유도 | 234 | 165 | 66 |
| 주줄기 강체 | 16 | 16 | 3 |
| 송이 연결 가지 / 중심 줄기 강체 | 5 / 14 | 5 / 14 | 1 / 5 |
| 식물 충돌체 | 376 | 90 | 90 |

초경량 모델도 기존 줄기 캡슐 68개, 열매 11개, 열매 쪽 꼭지 캡슐 11개를 유지한다.
여러 줄기 조각을 하나의 강체로 묶으면서 원래 캡슐 형상과 합산 질량·무게중심·관성을
보존한다. 초기 줄기 충돌 형상 비교 오차는 0.001mm 미만이다. 식물 articulation
총질량은 원본과 같은 약 0.134458kg이다.

목표 꼭지의 3개 분절과 말단 관절은 유지한다. 나머지 10개 꼭지는 각각 하나의
탄성 가지로 묶고 말단 관절을 고정 연결로 합친다. 모든 열매의 파단 조인트는 유지한다.
잎·주줄기 잘린 가지는 light와 같이 보이지만 충돌하지 않는다.

**탄성 응답이 원본과 같다는 뜻은 아니다.** 스프링 계수 보정은 작은 각도의 일정한
모멘트에서 직렬 유연성을 맞추는 근사다. 국소 휘어짐과 진동 모드는 달라진다.
묶인 강체 내부 조각끼리는 충돌하지 않으며, 부모·자식 및 자기 열매 충돌 제외의
범위도 강체 단위로 넓어진다. 최종 성공 후보는 full에서 다시 검증해야 한다.

## 측정과 검증

120Hz 물리 / 60Hz 제어 / PGS 64회 위치·4회 속도 반복 / armature 0.0005를 사용했다.
속도를 위해 물리 Hz나 관통 판정 기준을 낮추지 않았다. CPU에서는 CCD가 활성화된다.
ultralight는 매 물리 스텝의 USD 화면 좌표 쓰기를 생략하고, 화면을 그릴 때만 동기화한다.
접촉 보고·상태 읽기·매 스텝 0.5mm 관통 검사는 그대로 실행한다.

| 시험 | 시뮬레이션 시간 | 실제 실행 시간 |
|---|---:|---:|
| CPU full, 화면 없음 | 10초 | 12.54초 |
| CPU ultralight, 화면 없음 | 10초 | 7.54초 |
| CPU ultralight, 화면 표시 | 10초 | 9.24초 |
| CPU ultralight, 화면 표시, 후보 49 전체 실행 | 16.48초 | 13.71초 |

위 실행 시간에는 경로 계산·물리 실행·판정·결과 저장이 포함된다.
Kit 시작, 초기 장면 구성 및 RGB-D 촬영은 별도다. 초경량 측정의 장면 준비는
약 7.8~9.1초였고 Kit 자체 시작 시간은 그 밖에 추가된다.
단일 측정이며 다른 앱, 화면 크기와 후보 길이에 따라 달라진다. 원본/초경량의 비교에는
모델 축소와 USD 갱신 최적화가 함께 반영되어 있으며 강체 수만의 효과를 분리한 값은 아니다.

후보 49는 **수확 성공이 아니라 줄기 밀림 실패**였다. CPU 실행에서 관통 검사는
통과했다. 성공 사례를 새로 발견했다는 의미는 아니다.

초경량 CPU의 별도 물리 검사:

- 정지 상태 유지 및 초기 상태 재설정 통과.
- 열매에 0.2N 부하: 최대 변위 14.88mm, 해제 후 잔류 0.068mm.
- 부하 시험 중 최대 관절 연결 오차 0.036mm.
- 6N 부하에서 목표 열매만 파단, 재설정 후 복구.
- 미리 꼭지에 넣어 둔 고리의 4방향 유지 검사 통과. 로봇 진입 성공률 시험과 구분한다.

데이터는 `runs/20260921_ultralight/` 아래에 저장했다. 핵심 검증 요약은
`validation/ultralight_plant.json`을 확인한다.
관련 자동 테스트 55개가 통과했다. CPU/GPU·모델이 다른 재실행 결과를 동일한
대표 영상으로 판정하지 않는 검사와 복합 충돌체의 비목표 걸림 판정도 포함한다.

## GPU 병렬 실행의 범위

모델 옵션은 GPU 복제 환경에서도 사용할 수 있다. 그러나 **위 실시간 성능과
접촉 검증은 CPU 단일 환경 결과**다. GPU와 CPU의 접촉 결과를 동일하게 취급하지 않는다.
GPU 60Hz 또는 반복 수 축소 실험에서는 후보 49의 0.5mm 관통 기준 초과가 검출됐으므로
그 설정을 빠른 기본값으로 채택하지 않았다. TGS 60Hz 실험도 초기 파단 때문에 제외했다.
GPU에서는 `contact120`을 유지하고 `invalid_physics` 결과를 성공·실패 학습 데이터에서 제외한다.

GPU 4환경에서 후보 0·1·5·49를 각각 10초씩 실행한 측정은 46.41초였다.
이전 light의 같은 4환경 측정 66.08초보다 약 30% 짧다. 이 비교도 USD 갱신 최적화를
포함한다. 모든 실행은 10초 제한으로 `incomplete`이며, 접촉·상승 완료 검증이 아니다.
즉 **GPU 병렬 실시간 달성이나 64/256환경 성능을 증명한 결과는 아니다.**

GPU 설정을 낮춘 결과를 정상으로 보이게 하기 위한 판정 기준 완화는 하지 않았다.
접촉 여유 거리도 시험했지만 후보 49 문제를 해소하지 못해 새 기본 옵션에 넣지 않았다.
관련 개념은 [NVIDIA의 contact/rest offset 설명](https://nvidia-omniverse.github.io/PhysX/physx/5.1.1/docs/AdvancedCollisionDetection.html)을 참고했다.

`--max-control-steps 600`은 10초 처리 시간 측정용이다. 이 옵션으로 잘린 실행은
`incomplete`로 저장되며 정상적인 실패 데이터로 분류하지 않는다.
모델, CPU/GPU 장치, 코드가 달라진 결과는 같은 폴더에 이어서 저장하지 않는다.

### 병렬 용량 비교 재실행

2026-09-21 측정: 각 환경에서 동일한 후보 49의 첫 10초를 진행한 시간이다.
이 구간은 접촉 전 접근 구간이며 초기화·계획은 제외한다.

| GPU 환경 수 | 실제 처리 시간 | GPU 1환경 대비 합산 처리량 |
|---|---:|---:|
| 1 | 22.26초 | 1.00배 |
| 16 | 62.96초 | 5.66배 |
| 32 | 106.88초 | 6.66배 |
| 64 | 200.27초 | 7.11배 |

32→64환경의 추가 처리량은 약 7%다. 환경 수만 늘리기보다 매 환경의 판정·상태 처리
비용을 줄이는 것이 우선이다. CPU 단일 환경 실시간 미리보기와 다른 실행 방식이므로
그 수치를 GPU 병렬 처리에 그대로 적용할 수 없다. 128환경은 이번에 측정하지 않았다.

모든 환경을 접촉 종료까지도 실행했다. 1·16·32·64환경 모두 약 17.917초 시점에 같은
0.521mm 관통이 검출돼 `invalid_physics`로 종료됐다. 0.5mm 기준은 유지했다.
복제 간 경로·상태·접촉 결과는 일치하고 reset/파단 API 검사는 통과했으며,
환경 간 접촉 혼선과 네이티브 PhysX 오류는 없었다. **병렬 복제는 통과했지만
이 경로의 GPU 접촉 검증은 탈락했다.** 정상적인 실패/성공 데이터로 사용하지 않는다.

64환경의 전체 재생 376.16초 중 네이티브 물리 계산은 56.87초,
쓰기·물리·읽기 바깥의 판정·상태 처리 등은 288.08초였다. 실행 CPU는 약 110%
(코어 1.1개 분량), 전체 GPU 메모리 최대 3534MiB였다. 다른 사용자 세션을 유지한
단일 측정이다. 다음 개선 대상은 환경별 판정 처리와 GPU 접촉 안정성이다.

원시 기록과 표: `runs/20260921_231100_ultralight_gpu_scale/benchmark.md`,
추적 가능한 검증 요약: `validation/ultralight_gpu_scale.json`.

`ultralight_scale_benchmark.py`는 저장된 후보 49 경로를 각 환경에 동일하게 재생해
1·16·32·64환경의 처리 시간과 복제 일관성을 비교한다. 서로 다른 경로 탐색이나
계획 작업자 성능 시험은 아니다. 화면과 RGB-D 촬영 없이 실행하며, 10초 구간의
처리 시간과 실제 접촉 종료까지의 결과를 별도로 기록한다.

```bash
/root/isaaclab_env/bin/python nvidia-sim/rl/ultralight_scale_benchmark.py \
  --fixture nvidia-sim/rl/runs/20260921_213000_single_view_batched/results/candidate_00049 \
  --env-counts 1,16,32,64
```

날짜·시간으로 시작하는 `runs/*_ultralight_gpu_scale` 폴더에 JSON/CSV/Markdown과
환경별 상태·접촉 기록을 저장한다. 기존 사용자 세션은 종료하지 않으며, 측정된 GPU
메모리는 기존 세션을 포함한 전체 사용량이다. 영상은 이 속도 비교에 포함하지 않는다.
복제 결과 일치와 물리 유효성을 별개로 검사하므로 동일한 관통 오류가 복제됐다고
접촉 검증에 통과한 것으로 처리하지 않는다.
