# 최종 GPU 조합의 접촉·힘 검토

190DOF/200Hz와133DOF/220Hz의 실제 GPU 전체 실행에서 선택한 벨트 정책은 통과했다. 실제 접촉 기록을 다시 읽은 판정도 GPU와 정확히 일치했으며, 계측을 추가해도 기존 clean 실행의 전체 상태·힘·분리 이벤트는 바뀌지 않았다. 이것은 실물 벨트나 토마토 손상 한계를 검증했다는 뜻은 아니다.

## 이번에 허용한 범위

정확한4개 벨트 충돌체에만 과실·가는 꼭지 겹침2mm를 적용했다. 닫기·재닫기·벨트를 돌리며 닫아 유지하기·두 열기 stroke에만 적용하고, 접근·이동·완전히 열린 hold에는 적용하지 않는다. 다른 부품/식물/과실 쌍은1mm를 유지한다. 충돌체·마찰·강성·힘·분리 조건을 이 정책으로 바꾸지 않았다. 원래 closing-only 및 잔류0.5초 시험은 별도로 보존했다.

정책 파일: [profiles/belt_strokes_2mm.json](profiles/belt_strokes_2mm.json). 일반 실행의 기본 정책을 전역으로 바꾼 것이 아니라 명시적으로 선택하는 실험 profile이다.

## 같은 입력의 실제 CPU/GPU 속도

아래 GPU는 계측 없는 clean 전체 실행이다. CPU는16개 native pool thread를 사용한 전체 실행이며, 원래1mm 진단을 기록하고 계속 실행했다. CPU의 새 정책 판정은 저장된 모든1mm 초과 이벤트를 정확한 벨트 매핑으로 다시 분류한 **후처리**다. CPU에서 새 GPU 판정기를 실행했다는 뜻은 아니다.

|표현|계산|전체RTF|가장 느린 단계RTF|분리수|선택 정책|
|---|---|---:|---:|---:|---|
|190DOF|GPU|3.505|1.010 (belt_finish)|5|통과|
|190DOF|CPU|4.013|1.008 (belt_finish)|5|미통과 (후처리)|
|133DOF|GPU|3.890|1.140 (belt_finish)|6|통과|
|133DOF|CPU|5.549|1.330 (belt_finish)|5|통과 (후처리)|

CPU133은 GPU133보다 빨랐다. 단일 환경에서 GPU가 CPU보다 빨라졌다고 주장하지 않는다. 두 backend의 물리 입력 MJB와 모델 배열 hash는 같지만, 실제 상태와 분리 결과까지 같지는 않다. 분리 개수만으로 어느 쪽이 실물에 더 정확한지도 판단하지 않는다.

CPU190은1mm 초과 비예외 접촉32개 중27개가 벨트2mm 범위에 들어갔고, 나머지5개는 부착 중인 Fruit07–Tool_R 부품 접촉(최대1.104122mm)이었다. CPU133은4개 모두 벨트 범위에 들어갔다. 이 수는 접촉 표본 수이며 서로 다른 열매 수가 아니다.

## 실제 힘을 분리해서 해석

힘은 실제 solve의 접촉력 벡터 크기(N)다. 열매–꼭지 CONNECT의 내부 하중이나 torque와 구분한다. 최대 겹침과 최대 힘은 서로 다른 접촉·시점에서 생길 수 있다.

|GPU표현|부착 중 과실–벨트 최대N|꼭지–벨트 최대N|다른 감시 접촉 최대N|분리 열매 예외 최대N|
|---|---:|---:|---:|---:|
|190DOF|7.104|11.944|6.879|10.184|
|133DOF|4.871|8.395|5.838|10.427|

190의 꼭지–벨트 최대11.944N과133의8.395N은 해당 과실이 이미 분리된 뒤 남은 꼭지에서 발생했다. 이를 부착 과실에 가해진 손상력이라고 부르지 않는다. 반대로 이 힘을 기록에서 제외하거나0으로 만든 것도 아니다.133의 전체 최대10.427N은 이미 분리된 Fruit03이 고정된 그리퍼 부품에 닿은 예외 접촉이다.

190의 부착 과실–벨트 최대7.104N 시점 CONNECT 하중은2.295N이었다.133은 Fruit04 분리 스텝에서 벨트4.871N, CONNECT1.218N/torque0.008352Nm이었다. 접촉력과 내부 분리 조건은 서로 다른 측정량이다. 손상 한계는 이번에 검증하지 않았다.

## 가는 꼭지가 벨트를 뚫었는지

실제 peak 접촉과 그 주변±0.15초의 저장 상태로 네이티브 기하 계산만 수행했다. 새 physics는 실행하지 않았다. 실제 contact solve에 대응하는 qpos[t]와 적분 후 qpos[t+1]를 따로 보존했다.

190에서 가장 깊은 꼭지–벨트 접촉은 distal04–왼쪽 PrototypeTread의1.675mm였다. 그때 Fruit04는 이미 분리되어 있었다. 변형되지 않은 벨트 box 내부에 꼭지 단면 전체가 들어간 표본2개가 있지만, 중심선은5mm 두께 벨트의 중간면 또는 반대편을 지나지 않았다. 중심선의 진입면 기준 깊이는0.850mm, 반경을 포함한 외곽은1.675mm로 중간면2.5mm 이전이었다. 이는 이번에 명시한 벨트 눌림 근사 안의 겹침이며, 실제 탄성 형상을 구현했다는 뜻은 아니다.

133의 네 peak 검토창에서는 단면 전체 매몰·양 끝 바깥을 잇는 중심선의 고체 통과가0개였고, 벨트 중간면/반대편 진입도 없었다. 가장 깊은 distal05–오른쪽 벨트는1.304mm였다. 이 검사는 선택한 창에 한정하며 전체 장면의 모든 기하 쌍을 증명하지 않는다.

벨트 외 고정 부품의 최대 감시 겹침은190에서0.997mm,133에서0.799mm였다. 고정 CAD를 벨트라고 넓혀 허용하지 않았다.

## 보존한 한계

- 이미 분리된 Fruit08–바닥 접촉에서190은20.173mm,133은13.910mm의 큰 겹침이 남는다. 기존 낙하 열매 예외로 중단하지 않았으며, 착지·수거 물리의 정확성 증거로 쓰지 않는다.
- 접촉 거리·법선·접촉점·힘은 적분 전 solve, 국소 중심 좌표는 적분 후 geom 자세, attached는 제어 콜백의 캐시, timestamp는 실제 step-end다. 같은 시점의 측정으로 섞지 않는다.
- 물리 입력 MJB bytes / compiled model-array / 화면용 USD hash를 별도 필드에 저장했다. summary.model_sha256의 화면 호환용 hash를 물리 MJB hash라고 부르지 않는다. 이전 원자료를 수정하지 않고 해석 보정 addendum을 남겼다.
- 계측 witness의 RTF는 성능 순위에서 제외한다. clean 대조와 전체 물리 배열·이벤트가 정확히 같고, 두 witness 모두 재판정 event·class max·허용 횟수가 실제 GPU와 정확히 같다.
- `training_eligible=false`, `harvest_success=null`을 유지한다. 연결 해제 수는 수거 완료나 실물 수확 성공 수가 아니다.
