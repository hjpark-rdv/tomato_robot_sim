# 벨트 수확 속도와 접촉 겹침 허용치 비교

2026-10-10 KST. 브랜치 `codex/s300-harvest-isaac-20261009`, 시작 커밋 `34d681e`.
이번 시험은 같은 별도 5mm 벨트 접촉면 시험안 `assembly_tread5`를 사용한다.
원래 V5.1 CAD 또는 별도 V6의 성능 검증으로 해석하지 않는다.

## 결과와 사용할 설정

기존 전체 30.5초 수확 순서는 headless 480Hz에서 221.770초가 걸렸다.
같은 전체 식물과 충돌체를 유지한 TGS120/32는 52.691초로 약 4.21배 빨라졌고,
10번 열매의 native 연결부 파단·낙하와 개방·후퇴까지 완료했다.
TGS60/64는 38.126초(0.800배속)에 전체 동작을 완료했지만 분리 0개였다.
따라서 빠른 동작 확인과 분리 확인의 설정을 구분한다. 완전한 실시간 수확이나
여러 열매 동시 수확을 확보했다는 뜻은 아니다.

| 용도 | 물리 | headless 처리 s | 실시간 대비 | native 분리 | 최대 겹침 mm |
|---|---|---:|---:|---:|---:|
| 이전 기준 | PGS64/4, 480Hz | 221.770 | 0.138배 | 1 | 0.246 |
| 빠른 동작 확인 | TGS64/4, 60Hz | 38.126 | 0.800배 | 0 | 0.948 |
| 분리 확인 | TGS32/4, 120Hz | 52.691 | 0.579배 | 1 | 0.588 |

새 두 설정은 그리퍼와 **현재 송이의 열매 사이만** 겹침 중단값을 0.5→1mm로
완화한 opt-in 진단이다. 열매끼리, 주줄기·꼭지·다른 송이·거터·팔·바닥과의
활성 접촉은 기존 0.5mm를 유지한다. 초기 상태도 0.5mm 검사한다.
충돌 mask, 형상, 질량, 마찰, 강성, actuator, 파단값을 바꾸지 않았다.
Hz와 solver/반복 수 변경은 수치 동역학을 바꾸므로 480Hz와 물리 동등성을 주장하지 않는다.

화면을 켠 독립 재실행도 완료했다. 빠른 설정38.526초(0.792배), 분리 설정52.354초(0.583배).
같은 설정의 headless와 GUI는 각각1,831/3,661개 표본의 시간·명령·실제 팔/식물 상태·
벨트 명령이 모두 bit-exact였다. 120Hz 1thread/2threads의 실제 상태도 bit-exact였다.

## 어디서 기준을 넘었는가

- PGS60: 닫기 중 오른쪽 추가 벨트면 ↔ `Truss_02_Fruit_09`, 0.506mm.
  1mm로 완화해 계속 실행하니 0.05초 뒤 최대 1.354mm로 증가했다.
- PGS120: 닫기 중 오른쪽 추가 벨트면 ↔ 목표11번, 0.506mm.
- TGS60/64: 오른쪽 상판 `R/part_249` (`R_C02_upper_deck`) ↔ 7번,
  16.316667초에 최대 0.947617mm, 단일 접촉점 힘 1.78672N.
  전체 완료 실행에서 0.5mm 초과는 이 한 물리 표본뿐이었다(약 16.7ms).
- TGS120/32: 왼쪽 상판 `L/part_127` (`L_C02_upper_deck`) ↔ 8번,
  18.591667초에 최대 0.588303mm, 단일 접촉점 힘 2.34391N.
  전체 완료 실행에서 0.5mm 초과는 이 한 물리 표본뿐이었다(약 8.3ms).
  10번의 native 분리는 18.583333초 벨트 단계에 발생했다. 목표11번은 분리되지 않았다.
- PGS60의 그리퍼–열매2mm/같은 송이 열매끼리1mm 시험도 왼쪽 벨트–10번이
  최대3.539822mm 겹치며 중단됐다. 중단 로그 첫 두 점보다 전체 contacts의 최대값이 크다.
  이 결과를 보고 기준을 더 올리지 않았다.

힘은 impulse 크기/physics dt로 계산한 **단일 접촉점 값**이다. 합력이나 실물 손상
한계가 아니다. 시간은 물리 timestamp의 표본별 초과 시간이며 스텝 사이 연속 검증은 아니다.
겹침 허용은 재료가 실제로 눌린다는 모델이 아니며 충돌 계산을 생략하지 않는다.
허용치 변경 자체가 빨라지는 원인은 아니다. 낮은 Hz/반복 수로 계산을 줄인 실행이
작은 순간 겹침 때문에 중단되지 않도록 하는 진단 조건이다.

## 변경과 회귀 검증

- `motion_contact_guard.py`: manifest의 정확한 현재 송이 과실 collider와 stage에서
  확인한 그리퍼 collider 목록으로 접촉쌍별 중단값을 설정한다. 이름 일부가 비슷한
  다른 송이나 바디를 허용하지 않는다. 모든 원래 접촉·힘·겹침은 그대로 저장한다.
- `run_motion.py`: `--fruit-contact-limit-mm`와 별도 `--fruit-fruit-limit-mm`.
  기본값은 모두0.5mm. 현재 opt-in은 정확한 native callback 매핑의 단일 환경으로 제한한다.
- `contact_tolerance_evidence.json`: 기존0.5mm 초과 여부, 물체쌍, 깊이, 힘,
  물리 표본수·누락 간격을 고려한 연속 표본 시간을 기록한다.
- 기존 `benchmark_motion.py`, 실제 실행기, 상태 뷰어, 분석기, 영상 렌더러를 재사용했다.
  새로운 학습/수집/RL 파이프라인을 만들지 않았다.
- PGS60 및 TGS60의 엄격/완화 실행은 엄격 실행 중단 시점까지 `time`, `command`,
  `robot_q`, `poses`, 벨트 명령 배열이 bit-exact였다. 중단 판정만 변경한 근거다.
- 관련 자동 검사81개 PASS. 원래 기본 guard, 허용하지 않은 대상/역순쌍,
  모든 raw 접촉 보존, CLI 오류, 중복 접촉 표본과 시간 공백을 검사했다.

## 전체 시도와 성능 해석

새 headless16회와 GUI2회를 기록했다. 실패한 설정도 모두 결과표에 포함한다.
TGS60/32·60/48·90/48은 2.6~4.1mm 겹침으로 중단돼 채택하지 않았다.
120Hz의 CPU1thread는57.135초로2threads보다 느렸다.
기존 target-truss 근사(다른 송이 굽힘 고정)는42.660초로 빨랐지만 분리0으로 바뀌어
이번 권장 설정에 적용하지 않았다. 기본 full612DOF와 전체 충돌체를 유지한다.

처리 시간은 물리 루프의 제어·simulate·fetch·상태 읽기·접촉 기록을 포함한다.
앱/장면 준비, 계획·자기충돌 검사, 결과 저장, 사후 렌더 시간은 별도다.
기존221.770초 중 simulate215.69초가 대부분이었다. simulate에는 callback11.49초가
포함되므로 둘을 합산하면 안 된다. 새 설정의 대규모 병렬 처리량은 측정하지 않았다.
이전 GPU/CPU 풀 벤치마크를 이번 분리 모션의 속도로 간주하지 않는다.
