# 과실 통과 좌표와 꼭지 안착 좌표를 분리하는 다음 실험

기준: dc01b3bd83e8fdf98cf2f097a767580b427bd9a5. 별도 브랜치 codex/aperture-transit-20260927.

## 1. 이번 재검토의 근거와 한계

HOOK_SEATING_SERVER_RESULTS_KO.md, validation/hook_seating_server_20260927의 inputs/robot_under/candidates.json, planning_inputs.json, seating_goals.json, endpoint_results.json과 dataset_motion.py를 대조했다.

27개 계획, 새 동작 물리 실행0개, 기존 baseline 물리1개라는 분모를 유지한다. 일부 정적 끝 자세가 유효한 것은 전체 접근 가능성이나 기계적 유지 성공을 입증하지 않는다. 동영상 전 프레임을 독립 검증하거나 서버에 SSH로 접속해 새 물리를 돌리지는 않았다.

seating_00_under는 최종 안착 위치의 XY를 고정한 채 세계 Z로40mm 올라간다. 이때 과실 중심의 RING 좌표는 끝 자세에서 약[-20.9968,16.2516,6.0567]mm이고, 고리 평면 투영 오프셋은21.8529mm다. 입력 과실 경계구 반지름은13.9096mm다. 반지름27.5mm/와이어1mm인 이상적인 원의 중앙 통과 여유는12.5904mm이며,32분절 현으로 계산하면 약12.5573mm다.

이 수치는 끝 자세 자체를 거절하는 조건이 아니다. 과실이 고리 평면을 통과할 때와 과실 어깨 위에서 꼭지를 안착시킬 때 필요한 좌표가 다르다는 설명이다. 기존 과실 충돌은 native preflight 기록에서 확인되며, 경계구의 겹침 크기를 실제 mesh의 침투량으로 해석하지 않는다.

독립적인32캡슐 반원과 입력 경계구로 국소 경유점 구간을 표본 계산하면 기존 수직 상승 최소 간격은 약-9.282mm, 중심 정렬 상승 후 위쪽 옆 이동은 약+2.289mm다. 이것은 단순 기하 비교이지 실제 온실·팔·마운트·다른 과실의 충돌 검사나 물리 결과가 아니다. 양의 경계구 여유도 로봇 추종 오차와 식물 변형을 보장하지 않는다.

## 2. 우선 실행할 경로

기존 정상 시작과 preapproach/approach 경유점은 유지한다.

1. 과실 아래에서 고리 중심의 평면 투영을 과실 중심에 맞춘다.
2. 기울기 변경이 필요하면 아직 아래에서 과실 중심을 기준으로 회전한다. RING 위치는 p=c-R*c_local로 함께 변경한다. Hook 원점이나 손목 원점에서 회전만 바꾸지 않는다.
3. 과실 중심이 고리 안쪽 중앙을 지나는 상태로 고리 법선 방향으로 올린다.
4. 고리 평면이 과실 어깨를 충분히 지난 다음, 원래 꼭지 안착 위치로 옆 이동한다.
5. 필요한 경우에만 짧은 법선 방향 정렬을 추가한다. 기존 끝 자세를 무조건 성공 상태로 취급하지 않는다.

seating_00의 기하 예시(world m, 회전은 원래 quaternion):
- 중심 아래: [-0.696152523661374,0.9158217278439791,0.4534833653902833]
- 중심 위:   [-0.696152523661374,0.9158217278439791,0.4934833653902833]
- 원래 안착: [-0.7022053187722946,0.8948237864349288,0.4934833653902833]

첫 비교는 roll/pitch를 추가하지 않은 이0번 목표부터 한다. 목표 지점과 회전을 그대로 두고 연결 방식의 기여만 확인할 수 있다. 각도 자유도가 더 많아야만 해결된다고 가정하지 않는다.

## 3. 추가 코드와 사용법

propose_aperture_transit.py는 기존 one-insert/one-seat 진단 후보만 변환한다. 새 엔진이나 실행기를 만들지 않는다. 기존 진단 경유점 스키마,16개 상한,IK/FCL/환경 검사/실행기를 그대로 사용한다. 원본 prefix와 hold/verify suffix는 보존한다.

중요: 원본 verify는 작은 기존 경유점일 뿐 부하 검증이 아니다. 출력에도 source_verify_is_not_load_validation=true를 기록한다. 이 도구는 실제 접촉/유지 양성 대조를 대신하지 않는다.

실제32개 와이어에서 RING 중심부터 와이어 표면까지의 최소 거리를 계산해 aperture-inradius-m에 넣어라. 과실 경계구가 실제 collision mesh를 포함하는지 확인한다. 예시0.02646m는 현재 명목32분절 반원의 보수적인 근사치이며 자산 검증을 대신하지 않는다. plane-buffer는 계획용 간격이며 물성을 바꾸는 옵션이 아니다. 비목표 힘 발생 범위는 실제 pair margin/gap과 추종 오차를 별도로 고려한다.

```bash
V=mujoco-benchmark/validation/hook_seating_server_20260927/inputs/robot_under
OUT=/root/docker_share/mujoko_debugging_data/NEW_aperture_proposals
python mujoco-benchmark/scripts/propose_aperture_transit.py \
  --source-candidates "$V/candidates.json" \
  --planning-inputs "$V/planning_inputs.json" \
  --candidate seating_00_under \
  --wire-radius-m 0.001 --aperture-inradius-m 0.02646 \
  --plane-buffer-m 0.001 --output "$OUT"
```

candidates.json과proposal_report.json만 만든다. replay_assets나실행trace는 만들지 않는다. 동일 모델/초기 상태/코드해시를 대조한 새 실행 폴더에 기존 자산을 읽기 전용으로 재사용하고 기존 plan_candidates.py로 계획한다. 실제 생성된 관절 명령 배열을 전 구간 native preflight에 통과시켜라. 이 제안기의 기하와 joint 보간 후의 실제 경로는 동일하다고 가정하지 않는다.

새 seat 단계는 기존 planner의 rise 전용2mm/s 분기가 아니라 기본35mm/s 분기로 들어갈 수 있다. 이 제안기는 minimum_seconds를 명시해 최종 옆 안착 이동을2mm/s 이하의 명목 cubic 속도로 제한한다. 이동은10mm/s 명목 상한을 사용하며 생산 속도 설정은 변경하지 않는다.10초 경유점 상한을 넘는 이동은 분할한다. 실제 TCP/관절 속도·가속도는 생성trace와 실행에서 다시 검사한다.

## 4. 목표 생성기에 추가할 접근성 조건

- 목표 꼭지와 뒤쪽16개 와이어의 끝 자세뿐 아니라 전체32와이어, 마운트g410, 팔과환경을 검사한다.
- 각 목표는 통과용 중심 정렬 상태 또는 열린 입구로 빠져나가는 상태까지의 짧은 연결 증거를 함께 갖게 한다. 단순 IK 성공은 연결 성공이 아니다.
- 단계별 과실-고리 상대 좌표, 최초/최소 여유, 접근구간IK branch와 전체trace 검사 결과를 저장한다.
- 통과 중에는 과실 투영과 단면 여유를 우선하고, 마지막에만 꼭지를 뒤쪽 안착 영역으로 보낸다. 구형 경계는 계획용 보수적 단순화이며 탈락을 실제 불가능으로 라벨링하지 않는다.
- 원래 goal을 내보내는 단계의 검증과 실제 부하 상태의 동역학 검증은 구분한다. 음수 기하gap을 가진 정적 후보를 자동 성공으로 만들지 않는다.

중심 통과 방식이 비목표 구조에 막히면 두 번째 경로군은 정적 끝 자세에서 고리를 local -X로 이동해 목표 꼭지를 +X 열린 쪽으로 빼는 연결을 역으로 검사한다. 전체 목표 캡슐이 실제 와이어 입구 바깥에 오는 거리까지 구하되32와이어/과실/마운트/팔 충돌을 전부 검사한다. 이 정적 비접촉 경로를 정상 시작에 연결해 앞으로 실행한다. 접촉한 식물 동역학을 거꾸로 재생하면 성공한다는 가정은 하지 않는다. 이 두 번째 경로군은 이번 제안기에 구현하지 않았다.

## 5. 접촉·유지 양성 대조

정지한 양성 기하 fixture에서 힘이 작다는 사실 자체는 실패가 아니다. 부하가 없거나 충분한 실제 상대 이동이 없으면 기하적으로 가까워도 힘이 작을 수 있다. 최대 힘 하나나timer만으로 포획 성공을 선언하지 않는다.

같은 모델·물성·제어기에서 이미 안착한 시작 자세를 쓰는 loaded fixture를 별도로 만들고, 선택 와이어에서 목표 꼭지 쪽을 향하는 공통 법선 방향으로 제한된 작은 이동을 준다. 정체성,실제 이동,접촉력,상대 자세를 함께 측정한다.0.5mm/1.0mm의 두 변위 상한을 사전에 정하고 물리유효성·비목표 힘 조건을 위반하면 중단한다. 이것은 접촉대조 실험 예산이며 정상 시작 자동 진입 성공에 포함하지 않는다. 실제 이동이 추종오차에 묻히면 부하시험이 성립하지 않았다고 기록한다.

음성 대조는 같은 시간·제어조건에서 열린 쪽으로 벗어나는 자세, 과실 중심만 들어온 자세 또는 다른 꼭지 접촉을 사용한다. 무부하 정지와 부하 유지, 부하 해제 후 이탈을 구분한다. initially_seated=true를false로 바꾸어 timeline_evidence를 통과시키지 않는다.

정상 시작 동작의 유지 증거는 다음이 함께 있어야 한다.
- 실제 외부 초기 상태에서 목표 꼭지가 유효 공간으로 들어오는 시간 이력.
- 정확한 목표꼭지×뒤쪽와이어의 안쪽 안착과 의도된 접촉.
- 사전 선언한 방향의 실제 부하/변위를 주는동안 목표 정체성과 안착이 유지됨.
- timestamp가 연속인 hold1초와 별도verify 구간. 기존 보고 하한0.01N과 물리유효성0.5mm를 바꾸지 않는다.
- 목표만이 아니라 전 로봇 비허용 힘,잘못된 꼭지,침투,추종오차를 검사.

열린 반원은 모든 방향의 이탈을 막는 cage가 아니다. 한 방향 부하에서 버텼다는 결과를 모든 방향 유지나파단 수확 성공으로 해석하지 않는다. 특히 수확에 쓸 당김 방향이 시험한 접촉법선과 다르면 그 방향도 별도로 검증해야 한다.
