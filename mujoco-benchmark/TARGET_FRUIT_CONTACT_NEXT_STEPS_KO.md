# 목표 과실의 가벼운 접촉을 허용하는 제한 SIM 재시험

작성: 2026-09-28. 기준 `93b86a9`(서버 결과 `dc01b3b` 포함).
브랜치: `codex/target-fruit-contact-20260928`.

## 사용자 요구 변경과 현재 증거

사용자는 **타깃 과실을 고리 와이어가 스치거나 살짝 치는 것은 허용**한다고 명확히 했다.
따라서 이전 문서의 목표 과실 무접촉 조건을 이번 별도 진단에서 해제한다.
이는 임의로 성공 기준을 낮추는 것이 아니라 명시적인 작업 요구 수정이다.
다른 과실/꼭지, Rachis, 주줄기, 거터, 팔/마운트 접촉까지 허용한 것은 아니다.

`dc01b3b`의 `under_results.json`에서 최종 5경로는 모두 목표 Tomato_02와 와이어 접촉을
최초 위반으로 보고했고 `complete=false`다. 첫 겹침 0.022~0.158mm는 최대 겹침이나
실제 물리 침투가 아니다. 그 이후의 다른 충돌 여부는 이번에 끝까지 재검사해야 한다.
초기 12경로의 마운트-다른 열매/가지 충돌은 별도 문제다. baseline에도 실제 비허용 힘이
기록되어 있다. 접촉 허용만으로 꼭지 안착/유지가 해결됐다고 주장하지 않는다.

## 구현

`scripts/target_fruit_contact_trial.py`는 새 출력 디렉터리에서만 실행하는 도구다.
기존 생산 파일, 모델, 학습 라벨, 원본 경로, 물성을 수정하지 않는다.

1. 실제 Hook의 활성 캡슐에서 CAD 반원/반지름/평면 조건으로 32개 와이어를 식별한다.
   g번호 범위나 Hook 전체를 허용하지 않는다. 마운트/팔은 제외한다.
2. 정확한 타깃 과실 충돌체 하나와 그 와이어들의 접촉만
   `insert/seat/hold/verify`에서 새 진단 정책에 추가한다.
   기존 목표 꼭지 2개 × 뒤쪽 와이어 16개 × `seat/hold/verify` 정책은 유지한다.
   phase 경계에서는 양쪽 phase가 허용해야 한다. 준비 단계 접촉은 이번 범위 밖이다.
3. 조건부 정책으로 **전체 경로**를 검사한다. 다른 금지 충돌 또는 검사 미완료이면 물리를
   호출하지 않는다. 무시한 목표 접촉이 가볍다는 것은 이 검사로 알 수 없다.
4. 명시적인 `--execute`와 힘/변위 중단값이 있을 때만 SIM 물리를 실행한다.
   실행 중 실제 접촉은 꺼지지 않는다. 매 physics step의 live solver/별도 MjData forward
   힘을 분리 관측하며, 목표 접촉 하중/변위, 비허용 힘, 침투, 수치 오류를 감시한다.
5. 가벼운 과실 접촉 / 목표 꼭지 접촉 / 비허용 접촉을 분리한다.
   과실 접촉은 절대로 `target_contact`(꼭지 안착 증거)로 바꾸지 않는다.
   기존 판정은 `legacy_evidence`에, 새 허용 범위의 증거는 `authorized_contact_evidence`에
   별도로 저장한다. `hook_success=null`, `training_eligible=false`는 항상 유지한다.

## 수치의 의미

- 실제 물리 침투 상한 **0.5mm**는 기존 수치 유효성 기준이다. 무상처 보증이 아니다.
- 첫 실행 제안: `--max-target-force-n 1.0`, `--max-target-displacement-m 0.005`.
  **새로운 보수적 실험 중단값일 뿐, 검증된 토마토 손상 임계값이나 사용자 지정값이 아니다.**
  중단 시 자동으로 상향하거나 과거 실험을 실패로 재분류하지 않는다.
- 목표 힘은 과실과 의도된 꼭지 접촉의 **접촉별 힘 크기 합**이다. 접선력도 포함하며,
  반대 방향의 힘을 상쇄하지 않는다. 세계좌표 합력/피부 압력과는 다르다.
- live와 private-forward의 서로 다른 시점 힘을 더하지 않고 각각 한계를 검사한다.
- 비허용 힘은 기존 보고 하한 0.01N 이하로만 설정 가능하다. 이번 도구는 모든 금지 접촉의
  힘 크기 합을 사용하므로 과거 단일 법선력 최대보다 보수적이다. 원래 수치도 보존한다.
  0.01N 미만도 원자료에서 삭제하지 않는다. 이를 완전한 0접촉이라고 표현하지 않는다.
- 중단은 현재 SIM step 결과를 기록한 뒤 다음 step을 진행하지 않는 것이다.
  실제 로봇 감속/안전정지 제어가 아니며 이미 발생한 힘을 취소하지 않는다.
- 강체 과실 모델과 이 자료만으로 멍, 표피 손상, 압력에 대한 실물 안전성을 보증하지 않는다.

## Codex 실행 순서

### 1. 보존과 연결 확인

현재 branch/HEAD/status와 원격을 확인하고 별도 worktree/작업 브랜치를 사용한다.
`mjlab-performance`를 직접 수정하지 않는다. 원본 결과/미커밋 변경을 삭제하지 않는다.
위 브랜치를 기준으로 작업한다. 새 경로를 먼저 만드는 것은 이번 우선순위가 아니다.

서버 결과 `20260927_hook_seating_server` 안의 실제 `robot_under` 실행 폴더를 찾는다.
`manifest.json`, `replay_assets`, `candidates`를 갖는 run root여야 한다.
Git에 보존된 `inputs/robot_under`만으로는 대형 실행 자산이 모두 있지 않을 수 있다.
기존 `diagnostic_policy.json`을 base-policy로 지정한다. 예제 빈 정책으로 대체하지 않는다.
새 도구의 scope와 원본 물리 자산 해시를 확인한다. mapping이 맞지 않으면 실패 원인을
수정하되 와이어 수/타깃 이름 검사를 삭제해서 통과시키지 않는다.

### 2. 마지막 5경로를 재계획하지 않고 다시 검사

대상:
- seating_00_under
- seating_03_under
- seating_04_under
- seating_05_under
- seating_06_under

원래 명령/phase 배열 그대로 5개를 각기 새 출력 폴더에 검사한다.

```bash
$PY mujoco-benchmark/scripts/target_fruit_contact_trial.py "$RUN" \
  --candidate seating_00_under \
  --base-policy "$BASE_POLICY" \
  --output "$OUT/audit_seating_00_under"
```

조건부 통과/남은 금지 쌍/단계/미완료를 표로 만들고 전체 완료 여부를 확인한다.
기존 무접촉 검사 결과는 보존한다. 조건부 통과는 손상 없음이나 수확 성공이 아니다.
단순히 첫 과실 접촉을 건너뛰고 뒤의 검사 없이 실행하는 것은 금지한다.

### 3. 통과한 기존 경로를 힘/변위 감시와 함께 물리 실행

```bash
$PY mujoco-benchmark/scripts/target_fruit_contact_trial.py "$RUN" \
  --candidate seating_00_under \
  --base-policy "$BASE_POLICY" \
  --output "$OUT/trial_seating_00_under" \
  --execute --max-target-force-n 1.0 --max-target-displacement-m 0.005
```

도구는 실행 전 조건부 전체 검사를 다시 한다. 처음부터 물리 결과를 만들어내지 않는다.
`target_force_limit`, `target_displacement_limit`, `forbidden_force`, `physics_penetration`,
`invalid_physics`를 서로 다르게 해석한다. 실험 중단은 경로의 물리적 불가능 증명이 아니다.
새 접촉허용 경로의 실제 기하/힘/추종/걸림을 확인하는 것이 이번 목적이다.

현재 seat가 일반 이동속도 분기를 사용한다는 점은 주의한다. 힘/추종 문제만 남으면
허용 범위 확대나 물성 변경 대신 **같은 기하 경로를 한 번 느리게 재시간화**할 수 있다.
이것은 별도 후보/새 trace/hash로 저장한다. 기존 trace를 덮어쓰지 않는다.
2mm/s 명목 seat 상한은 재시간화 실험값이며 실제 TCP 속도도 측정한다.

### 4. 결과 파일과 영상

- contact_scope.json: 정확한 쌍/phase, 원본/진단 정책, 입력/코드 해시.
- environment_preflight.json/html: 목표 접촉만 예외인 전체 검사.
- target_contact_trial.json: 실행 여부, 완료/중단 원인, 기존/새 분류의 증거.
- authorized_contact_samples.json.gz: 매 step의 허용 과실/꼭지/금지 힘과 변위.
- seating_samples/contact_events: 기존 분류와 live/private 원자료.
- trial_states.npz: 초기/최대30fps/최종 상태. 영상용이며 접촉판정은 physics step 기록이다.

힘, 변위, 실제 침투의 최대값/발생시간과 접촉 지속시간을 집계한다. 단일 접촉 최대와
접촉별 힘 합을 구분한다. 대표 실행 2~3개를 기존 렌더러로 MP4에 저장한다.
중단된 영상은 중단시점/원인을 표시한다. 계획 영상으로 물리 성공을 대체하지 않는다.
꼭지 안착/유지/확인 동작은 기존 독립 기준으로 계속 검사하고, 정적 fixture를 정상
접근 성공으로 세지 않는다. 새 도구가 별도로 저장한 legacy 판정은 변경된 요구와
직접 비교하지 말고 접촉 분류 차이를 함께 설명한다.

### 5. 제한 예산과 종료

- 기존5경로 조건부 전체 검사5건.
- 정상시작 물리 최대5회(중단 포함), 재시간화/확인 물리 추가 최대2회.
- 다른 물체에 막히면 그 쌍/단계를 보존한다. 필요하면 기존 aperture 경로를 비교군으로
  2개까지 추가 계획할 수 있지만 물리 총7회 한도는 유지한다.
- 27개 기존 계획 전체나 7경로 접촉 시점 진단을 다시 시작하지 않는다.
- 목표 접촉 때문에만 막혔는지, 실제로 가볍게 스치고 통과하는지, 아니면 과도하게
  밀거나 다른 물체/꼭지 걸림이 병목인지를 구분한 뒤 한 라운드에서 종료한다.
- 접촉 허용 후 성공하리라고 가정하지 않는다. 0.5mm 물리 기준과 실제 충돌은 유지한다.

결과/테스트/대표 영상/남은 한계를 커밋하고 보고한다. 기존 관측/학습 포맷은 건드리지 않는다.

## 현재 검증 범위

로컬 순수 테스트44개 통과, native 테스트는 로컬 MuJoCo가 없어 미실행이다.
CI에는 기존 관련 회귀와 새 native 3개를 포함했다. 실제 CI 결과는 실행 로그로 확인한다.
실제 온실에서 새 CLI를 실행하거나 가벼운 접촉/꼭지 유지가 성립함을 확인한 것은 아직 아니다.
