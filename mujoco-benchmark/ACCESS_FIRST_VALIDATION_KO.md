## 숫자보다 중요한 확인 사항

1. 작은 native MuJoCo 모델에서 직선 연결이 벽에 막힐 때, 실제 OMPL RRTConnect가 벽 위쪽을 우회하는 경로를 반환했다. 해당 경로를 더 작은 간격으로 독립 검사했고, 시간화한 명령 배열에서도 우회가 유지됐다. 이는 이름만 다른 경로 후보를 만드는 시험이 아니라, 장애물 정보를 사용하는 실제 탐색 시험이다.
2. 공간을 가로막는 벽으로 연결되지 않은 경우 exact solution을 반환하지 않았다. 제한 시간 뒤 가까운 곳에 도착한 approximate solution을 성공으로 처리하지 않았다.
3. 시작 자세가 충돌하면 이를 무시한 탈출 경로를 만들지 않았다. 로봇 자기충돌 검사 결과도 동일하게 차단했다.
4. 첫 IK 해가 충돌하는 합성 관절 모델에서 다른 해를 유지했다. IK 함수가 보고한 오차가 아니라 실제 FK 잔차를 재확인했다.
5. 기존 `dataset_motion.plan()`을 직접 호출하는 연결 시험에서 선택한 관절 branch가 suffix에 사용됐고, 원래 환경의 시작 관절과 원본 후보는 변하지 않았다. 이 시험의 로봇 기구학은 작은 해석 모델이며 실제 RB5 전체 모델은 아니다.
6. 기존 고정 명령 배열 fixture 및 접촉 정책/자기 송이 소속/환경 검사 회귀가 통과했다.

## 변경하지 않은 것

기존 `dataset_motion.py`, `plan_candidates.py`, `RobotEngine`, 환경/접촉 검사기, 물성, 충돌 형상, 성공 판정, 학습 코드는 수정하지 않았다. 새 스크립트3개, 테스트3개, CI와 문서만 추가했다. 기존 파이프라인이 자동으로 이 계획기로 전환되는 것은 아니다.

## 아직 확인하지 않은 것

- 사용자 서버 대형 MJB/메시/pickle로 실행한 전체 경로 및 실제 물리 결과.
- 특정 온실 타깃의 접근 성공률 개선, 처리시간 및 메모리.
- 실제 토마토 모델에서의 다른 IK 해 확보 정도.
- 새 정상 시작 접근 영상 및 실제 꼭지 걸림/유지.
- 실제 하드웨어 안전성이나 RGB-D만 이용한 sim-to-real 전이.

원본 보고서가 보존한 영상과 원자료의 전체 디코딩을 여기서 재수행한 것은 아니다. 이번 판단은 해당 커밋의 보고서·계획기·접촉/환경 코드 검토 및 위 기능 시험을 근거로 했다.

## 서버 인수 기준

설계 문서의 3타깃/6계획/6물리 상한 안에서 기존 보간과 새 접근 계획을 비교한다. 정상 시작 접근 성공과 전체 작업 성공을 분리한다. `prefix_found`는 기하학적 접근 경로를 찾았다는 뜻이고, 정상 시작 물리 완주는 별도로 검증한다.

접근은 되는데 삽입이 막히면 이 접근 기능을 끝없이 고도화하지 않는다. 같은 준비 상태에서 국소 계획 대 제한된 RL 비교로 넘어간다. 접근이 개선되지 않으면 구현 오류 수정 최대1라운드 후, 시작·목표·충돌 모델 또는 독립적인 가능 경로를 확인한다.
