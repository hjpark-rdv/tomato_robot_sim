## 판단

현재처럼 경로군과 무작위 변수를 늘린 다음 전체 경로가 충돌하면 버리는 작업은 일단 중단한다. 다만 이 결과가 RL이 더 좋다는 증거도 아니다. **장애물을 피해 준비 자세까지 이동하는 문제와, 식물과 접촉하며 삽입·걸림을 만드는 문제를 분리**한다.

이는 문제를 계속 잘게 나누기 위한 진단 추가가 아니다. 앞부분에 실제 장애물 회피 탐색을 넣어, 뒤쪽 방법을 비교할 수 있는 실행 상태를 확보하려는 변경이다. 한 라운드의 종료·전환 조건을 아래처럼 고정한다.

## 서버 자료에서 확인한 사실

원래 파일럿 240제안 중 239개는 IK/로봇 검사를 통과했지만 239개 모두 환경 검사에서 차단됐고 물리 실행은 0이었다. 네 경로군의 준비·접근이 48개 그룹에서 동일했으며, 23그룹의 92경로는 분기하기 전부터 막혔다. 이는 그 네 가지 국소 동작의 물리 성능을 비교한 실험이 아니다.

그러나 모든 실패를 prefix 탓으로 돌려서는 안 된다. 다른 다수는 insert에서, 왼쪽 우회 한 건은 seat에서 다른 꼭지와 충돌했다. 준비 경로를 고쳐도 삽입은 별도 실패할 수 있다.

`nvidia-sim/rl/dataset_motion.py`는 준비 목표의 IK를 현재 관절값 한 개로 시작해서 구하고, 시작에서 그 해까지 관절 직선 보간한다. 이후 경유점은 Cartesian 직선·회전 보간과 연속 IK다. 환경 검사는 생성 이후 적용된다. 따라서 **현재 기본 계획기는 장애물 정보를 이용해 우회로를 찾지 않는다.**

측면 입구 방향 수정은 필요할 수 있지만, 입구를 돌린다고 팔꿈치/손목의 다른 IK 해가 자동으로 선택되는 것은 아니다. 보고서의 고리-link3 자기충돌을 단순 입구 방향 파라미터만으로 해결했다고 볼 수 없다.

## 이번 구현

### access_route.py

직접 만든 RRT 대신 **OMPL 2.0.1 RRTConnect**를 사용한다. 기존 FCL 자기충돌 검사와 동일한 MuJoCoScene의 실제 충돌 형상을 탐색 중에 호출한다. 고리를 막힌 구로 바꾸거나 다른 온실 근사 모델을 새로 만들지 않는다.

서로 다른 IK 초기값에서 나온 해를 FK 오차·관절 한계·자기충돌·환경 충돌로 선별하고 여러 해를 유지한다. 첫 해에 직선으로 못 간다고 대상 자체를 실패 처리하지 않고, 선택한 준비 자세까지 우회 경로를 탐색한다.

관절 범위로 좌표를 정규화해 미터 단위 리프트와 라디안 관절을 함께 다룬다. 반환된 경로는 중간 샘플까지 다시 검사한다. 속도 제한을 적용한 실제 명령 배열도 재검사한다. OMPL approximate solution은 채택하지 않는다.

### plan_access_then_task.py

기존 explicit pose 후보의 **마지막 approach 경유점**을 접근 목표로 삼는다. 기존 home/preapproach/approach 보간을 우회 계획으로 교체한다. 그 뒤 원래 insert/seat/hold/verify 목표는 유지하되, **선택된 IK 관절 해에서 다시 계획**한다. 다른 관절 해에서 만들어 둔 옛 suffix를 억지로 이어 붙이지 않는다.

산출물은 둘로 분리한다.

- `prefix/`: 정상 시작에서 준비 지점까지 이동하고 hold하는 명령. 실제로 준비 위치에 도달하는지 검증한다. 수확 성공으로 집계하지 않는다.
- `full/`: 위 경로와 원래 삽입·안착 동작을 연결하고 전체 환경 검사를 통과한 경우에만 생성한다.

둘 다 기존 `target_fruit_contact_trial.py`와 렌더러로 실행·표시할 수 있는 독립 run 폴더다. `access_result.json`이 경로와 candidate ID를 기록한다. 최종 관절 trace가 실행의 기준이며, action14 표현으로 축약하지 않는다.

### prepare_access_ablation.py

새 장면을 만드는 대신 기존 스냅샷을 사용한다. 기본 방위각 -45/0/+45도와 roll/pitch/elevation/twist=0을 기준으로 작은 비교군을 만든다. 이후 기울기는 한 축만 바꾼 별도 묶음으로 비교한다. 네 Sobol 벡터에서 모든 변수를 동시에 흔드는 실험으로 되돌아가지 않는다.

기존 경로군 생성기는 재사용한다. 낮은 기울기 후보도 실제로 도달 가능한지 검사해야 하며, 충돌 없는 준비 자세를 자동 보장하지 않는다.

## RL을 지금 어디에 쓸 것인가

**현재 바로 집에서 출발하는 전체 행동을 RL로 바꾸는 것은 권하지 않는다.** 이번 실패는 실제 접촉 학습의 실패가 아니라, 대부분 실행 전에 정해진 경로가 충돌해서 차단된 결과다. 같은 full-trajectory gate를 RL 앞에 그대로 두면 탐험도 차단되고, gate를 빼면 물리 탐험·관찰·보상·중단 설계를 새로 검증해야 한다.

그렇다고 RL을 배제하지 않는다. 준비 위치까지의 경로가 확보된 뒤에도 표면 접촉·삽입·회전에 반복적으로 막히면 **동일한 준비 상태 분포에서 국소 경로 탐색과 짧은 Cartesian RL 또는 residual RL을 직접 비교**한다. RL을 다시 한다면 모델 크기보다 정상 상태/성공 상태 분포, 행동 크기, 실제 제어기의 추종, 고정된 평가 기준을 먼저 맞춘다.

SIM의 정확한 꼭지는 교사 탐색에서 사용할 수 있지만, 실물에 없는 힘센서나 가려진 꼭지 GT를 실물 정책의 필수 입력으로 추가하지 않는다. 교사가 찾은 행동과 실제 RGB-D만으로 행동을 고르는 학생 모델은 별도 검증한다.

방법론 참고이며 토마토 성공의 증거는 아니다:
- OMPL RRTConnect: https://ompl.kavrakilab.org/classompl_1_1geometric_1_1RRTConnect.html
- 상태/경로 유효성: https://ompl.kavrakilab.org/stateValidation.html
- Python Nanobind API: https://ompl.kavrakilab.org/python.html
- IndustReal: https://research.nvidia.com/publication/2023-05_industreal-transferring-contact-rich-assembly-tasks-simulation-reality

## 한계

- 새로운 접촉 정책, 물성, 관통 기준, 로봇 제어기, 기본 계획기/생성기 수정은 없다. 기존 사용자 허용 범위인 목표 과실·자기 송이 Rachis 와이어 접촉은 유지한다.
- 환경은 초기 상태에 고정돼 있다. 움직이는 식물·추종오차·스텝 사이 충돌까지 보장하는 안전 인증은 아니다. 기존 실제 물리 감시는 실행 때 유지한다.
- 준비 목표 자체가 장애물 속에 있거나 모든 검토 IK 해가 자기충돌하면 이 목표로 가는 경로를 만들 수 없다. IK 초기값 소진은 절대적인 불가능 증명이 아니다.
- 삽입 경로 전체를 자동 재설계하지 않는다. 접근만 통과해도 별도로 저장해서, 다음 문제를 실제로 분리해 볼 수 있게 한다.
- 시간화는 RRT 경유점마다 감속·정지하는 보수적인 방식이다. 인간처럼 연속적으로 매끄러운 최종 동작이나 관절 가속도/토크 보증은 아니다.
- OMPL RNG는 프로세스 전역이다. 별도 CLI 프로세스와 실제 반환 경로·seed·버전을 보존하되, 같은 프로세스 내 여러 호출의 비트 단위 재현성을 주장하지 않는다.
- `--search-seconds`는 전체 작업의 강제 종료시간이 아니다. IK 한 번과 최종 검사 호출은 별도 시간이 들 수 있다. 서버 실행에는 300초 외부 timeout을 사용한다.
- 큰 MJB/메시/pickle은 서버/NAS에만 있다. 여기서 온실 물리나 새로운 실제 동작 영상을 확인했다고 주장하지 않는다.

1. 기존 사용자 작업을 보존하고 이 브랜치를 별도 worktree에 가져온다. 원본 브랜치에 merge/reset/clean하지 않는다. `d1fdc7c` 이후의 본인 변경이 있다면 먼저 비교한다.
2. 기존 Torch/FCL 계획 요구사항과 MuJoCo 3.13.0, ompl==2.0.1을 같이 사용할 수 있는 격리 환경을 준비한다. 기존 Isaac 환경을 통째로 업그레이드하지 않는다.
3. 테스트와 도구 import를 확인한다. 새 native 시험은 작은 모델의 실제 OMPL/거리 검사다. 온실 통합 성공으로 해석하지 않는다.
4. 통과 장면에서 서로 다른 타깃 3개를 먼저 고른다. 공유 prefix 차단 사례, 측면 자기충돌 사례, late-seat 사례를 포함한다. 새 결과를 보고 좋은 타깃만 바꾸지 않는다.
5. 우선 동일 후보·동일 준비 위치·동일 삽입 목표에서 기존 보간과 새 접근 계획을 비교한다. 타깃당 최대 2개 접근 문제, 전체 6개까지만 계획한다. 각 문제는 IK seed8, 충돌 유효 branch3, branch당 RRT8초, 공유 탐색60초/상태검사30000회를 사용한다.
6. 준비 목표 자체가 유효하지 않을 때만 낮은 기울기 묶음의 후보 하나를 대안으로 사용한다. 여러 변수를 한꺼번에 수정하지 않는다. 대체 후보도 위 6개 예산에 포함한다.
7. prefix가 유효하면 정상 시작에서 실제 물리로 실행한다. suffix가 차단돼도 prefix 실행을 통해 접근 개선 여부는 확인한다. 정상 시작 없이 준비 위치로 teleport한 결과를 접근 성공으로 세지 않는다.
8. suffix는 선택된 새 IK branch에서 재계획하고 전체 경로를 다시 검사한다. 통과한 full 경로만 정상 시작 물리로 실행한다. 전체 물리 상한6회, 중도중단도 포함한다.
9. 최대3개 MP4: 이전 명목 차단 경로, 새 실제 접근, 가능한 경우 full 실행 또는 대표 잔여 실패. 명목/실제 표기를 구분한다.
10. 결과표: 타깃/후보, 시작 유효성, FK 유효 IK 해 수, 충돌 유효 해 수, 접근 연결, 접근 실제 완주, suffix 계획/차단 지점, full 실제 실행, 시간·상태조회 수. 수확 증거는 기존처럼 별도로 기록한다.

## 계속할지 전환할지

**3타깃 중 2개 이상에서 새 접근 경로를 찾고, 적어도 1개가 실제 정상 시작에서 준비 위치까지 완주하면** 접근 기능의 1차 이정표를 통과한 것으로 본다. 이것은 성공률 추정이 아니라 개발 판단 기준이다. 이후 접근 도구를 더 늘리지 말고 그 준비 상태에서 국소 삽입 방법을 비교한다.

접근은 되는데 접촉/삽입에서 계속 실패하면, 같은 준비 상태·물성·관측·평가와 고정 계산 예산으로 국소 탐색 대 RL을 비교한다. RL의 반환 보상이 아니라 단계별 실행 증거와 보류/오류율을 비교한다.

한 라운드에서도 접근 개선이 없으면 구현 오류 수정 라운드 최대1회만 허용한다. 그 뒤에는 시작 자세/목표 위치/충돌 모델의 타당성과 독립적으로 알려진 가능한 접근 경로를 확인한다. 이때만 다른 계획기나 설치/로봇 배치 변경을 판단하고, 같은 무작위 곡선을 무한히 늘리지 않는다.

물리 모델이 이미 알려진 양성·음성 접촉 fixture조차 구분하지 못하면 모델/평가 적합성 문제로 분리한다. 1.4mm를 측정된 현실 오차 범위라고 단정하지도, 접촉력0을 곧 실물 불가능이라고 단정하지도 않는다.

전체80열매/신규 장면 확장은 접근과 국소 실행에 유효한 증거가 생긴 다음이다. `training_eligible=false`, `hook_success=null`, `impossible=null` 유지. 현재의 미확정 라벨로 RGB-D 모델을 대량 재학습하지 않는다.
