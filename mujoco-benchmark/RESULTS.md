# 원본 식물의 MuJoCo 이식: 1차 비교 결과

2026-09-22 KST. 기준 코드 `8e0d820`, 식물은 기존 **full**이다.
결과: **엔진만 바꾼 원본 모델의 속도 이득은 작았다.** 별도 최적화 모델은 빨랐지만
물리 조건이 달라졌으며, 낮은 Hz에서는 여전히 오차가 발생했다.

[영상·RGB-D·비교표 통합 화면](outputs/20260922_002000_original_comparison/index.html)
에서 실제 움직임을 확인할 수 있다. 기존 Isaac 프로그램과 원본 USD는 보존했다.

## 무엇을 비교했는가

- Threadripper 3960X, 48 logical CPUs, RTX 3090 Ti 24GB.
- Isaac Sim 5.1 / MuJoCo 3.13.0. 양쪽 **CPU 물리**, RGB-D/영상은 NVIDIA GPU.
- 식물 90강체(열매 포함), 탄성 234 DOF, 열매 free-body 66 DOF.
  식물 collision 376개, 고리 collision 35개, 총 질량 0.720472kg.
- Isaac의 90개 joint prim은 탄성 78개, 기저 고정 1개, 열매 고정 11개다.
  MuJoCo는 탄성 hinge 234개, free joint 11개, weld equality 11개이며 기저는 world에 고정한다.
  joint 개수보다 구속 구조와 DOF를 함께 비교해야 한다.
- 로봇 암을 제거하고 같은 world 고리 궤적을 직접 재생했다. 양쪽 파단 비활성화.
- 기본값: 120Hz. Isaac PGS 64 position / 4 velocity iterations, CCD.
  MuJoCo implicitfast / Newton 최대 64 iterations / sparse / elliptic.
- 100개는 기계적 fixture 6개 + 후보49 기록 + 기존 로그 93개의 **서로 다른 기록 경로**다.
  각 기록의 실제 속도와 저장된 전체 prefix를 사용했다. 중단된 경로 뒤를 임의로 연장하지 않았다.
  짧은 기록을 우선 선정했으므로 100개의 완전한 수확 동작 처리량은 아니다.
- 1개 환경에서 1 → 10 → 100개를 순차 재생했다. **100환경 병렬 시험이 아니다.**
  기존 GPU 전체 로봇 파이프라인과 이 표의 시간을 직접 비교할 수 없다.

## 원본 120Hz, 동일한 100개 경로

총 시뮬레이션 시간은 양쪽 모두 997.683초다. 로딩/영상 생성 시간은 제외했다.

| 측정 | Isaac full | MuJoCo original-equivalent |
|---|---:|---:|
| 순수 physics step | 475.84초 | 433.06초 |
| 궤적 입력·상태/접촉 기록 포함 실행 | 502.16초 | 464.91초 |
| 실행 RTF | 1.987 | 2.146 |
| 관통 검사·결과 저장 포함 전체 | 565.27초 | 539.83초 |
| 최대 프로세스 RSS | 2054MiB | 707MiB |
| 평균 reset 1회 | 0.175ms | 3.969ms |
| 0.5mm 초과 관통 경로 | 0/100 | 0/100 |
| 0.5mm 초과 열매 부착 오차 경로 | 5/100 | 22/100 |
| 최대 열매 부착 오차 | 1.160mm | 3.202mm |
| 수치 불안정 | 0/100 | 0/100 |

전체 작업 시간 감소는 약 **4.5%**, 실행 시간 감소는 약 **7.4%**다.
메모리는 줄었지만 원본 MuJoCo를 빠르고 동등한 대체재로 확정할 근거는 부족하다.
특히 관통 0건이어도 열매와 꼭지의 연결 오차가 발생한 실행은 정상으로 보지 않았다.

## timestep과 별도 최적화

추가로 Isaac도 동일한 6개 fixture를 **240Hz**에서 실행했다. 72초 시뮬레이션을
입력·상태 기록 포함 **70.01초(RTF 1.03)**, 검사·저장 포함 **81.33초**에 처리했다.
6개 모두 관통/부착 오차 0.5mm 기준 이내였다(최대 관통 0.431mm, 부착 오차 0.372mm).
MuJoCo 240Hz의 67.06초(RTF 1.07), 전체 79.36초와 비슷한 수준이다.
양쪽 고리 입력과 초기 자세 동일성도 확인했다. [추가 검증 JSON](validation/comparison_240hz.json).
두 엔진 모두 화면·팔 없이 단일 환경을 순차 실행한 결과다.

| 설정 | 경로 수 | 실행 RTF | 결과 |
|---|---:|---:|---|
| Isaac 원본 240Hz PGS | 6 | 1.03 | 검사상 관통/부착 오차 초과 없음 |
| 원본 60Hz implicitfast | 6 | 비교 부적합 | 6/6 수치 폭주, 조기 종료 |
| 원본 120Hz implicitfast | 100 | 2.15 | 부착 오차 22개 |
| 원본 240Hz implicitfast | 6 | 1.07 | 검사상 관통/부착 오차 초과 없음 |
| 원본 480Hz implicitfast | 6 | 0.54 | 검사상 관통/부착 오차 초과 없음 |
| 원본 120Hz Euler | 6 | 2.11 | entry/lift에서 부착 오차 초과 |
| 최적화 120Hz implicitfast | 10 | 3.46 | 검사상 관통/부착 오차 초과 없음 |
| 최적화 60Hz implicitfast | 6 | 6.74 | 2개에서 관통 기준 초과 |

240/480Hz의 안정성은 **6개 fixture 범위**다. 100개 전체에서 검증한 것으로 해석하면 안 된다.
최적화 모델은 잎/잘린 가지 286개 collision을 끄고 열매 free joint/weld를 합쳤다.
질량·탄성 관절·줄기 캡슐·시각 형상은 유지하지만 파단은 불가능하고 원본과 다른 문제다.
최적화 60Hz에서는 stem push 1.229mm, 큰 밀림 1.037mm 관통이 검출됐다.

정상적인 수치 상태에서의 스텝 사이 터널링 의심은 이번 범위에서 0건이었다.
존재하지 않는 정상 터널링 사례를 만들어 성공/실패 영상으로 포장하지 않았다.
대신 원본 60Hz의 **수치 폭주**와 최적화 60Hz의 **관통 기준 초과** 영상을 제공한다.

## 움직임은 어느 정도 비슷했는가

아래는 120Hz의 동일 fixture에서 목표 열매 중심 최대 변위다.

| 동작 | Isaac | MuJoCo |
|---|---:|---:|
| 열매 접촉 | 26.51mm | 27.51mm |
| 꼭지 근처 접촉 | 9.06mm | 9.98mm |
| 주줄기 옆으로 밀기 | 16.64mm | 16.20mm |
| 아래 진입·상승 | 31.45mm | 38.10mm |
| 큰 밀림 fixture | 16.29mm | 16.89mm |

기본 밀림과 복원은 비슷했지만 진입·상승과 부착 제약에서는 차이가 커졌다.
접촉 fixture는 끝에서 목표 최대 변위의 약 99% 이상을 회복했다. 큰 밀림은 도구 복귀 후
목표 변위가 `max(1mm, peak의 10%)` 안에 유지되기까지 Isaac 약 0.49초,
MuJoCo 약 0.93초였다. 이것은 **정착 시간의 근사값**이며 자유진동 주기 측정은 아니다.
기록 prefix는 마지막 고리 자세를 유지하므로 자유 복원 실험으로 해석하지 않는다.
최대 변위 XYZ·최종 변위·꼭지/주줄기 변위·first contact는 각 result.json/CSV에 저장했다.

## 화면 표시와 RGB-D

10초 열매 접촉 fixture, 원본 120Hz. 물리 전용 처리량과 별도로 측정했다.

| 출력 모드 | 실제 시간 | RTF |
|---|---:|---:|
| MuJoCo passive viewer, DISPLAY=:0 | 5.73초 | 1.75 |
| MuJoCo RGB-D 640×480 / 15Hz | 5.63초 | 1.78 |
| Isaac RGB-D 640×480 / 15Hz | 약 7.9초 | 약 1.26 |

뷰어는 비동기 렌더링이다. 두 출력 모드의 작업 구성이 달라 작은 차이를 순위로 해석하지 않는다.
초기 EGL은 llvmpipe CPU 렌더러였으나 프로젝트 전용 NVIDIA 설정으로 다시 측정했다.
소프트웨어 렌더링 측정은 최종 GPU 표에서 제외했고, headless 물리 표에는 영향이 없다.
MuJoCo depth의 26개 가시 표본은 raycast 대비 오차 중앙값 약 0.001mm,
최대 약 0.361mm였다. MSAA를 끈 optical-Z이며 전체 픽셀/얇은 경계의 정확도를 보증하지 않는다.

영상은 총 16개다. 원본 양쪽의 stem/fruit/pedicel/entry-lift/후보49,
MuJoCo 240Hz 안정 접촉과 0.5배속, 60Hz 폭주, 최적화 모델의 접촉/관통을 포함한다.
오른쪽 검사 화면에서만 잎/잘린 가지 mesh를 숨겼다. 물리 결과를 다시 계산하지 않았다.
열매/꽃받침 원본 mesh를 사용하지만 상세 재질·줄기 skin·털의 외관 재현은 범위 밖이다.

## 검증 및 남은 차이

- 원본 native 질량/COM, 초기 배치, reset, 열린 고리, 스텝 사이 관통 검출,
  최적화 제약/질량 검사: 자동 테스트 **6개 통과**.
- 두 엔진의 1/10/100 시험에서 고리 명령 배열은 모두 동일했다.
  초기 위치 최대 차이는 약 0.000152mm이며 회전도 허용 수치 오차 이내였다.
- 10개와 100개 실행의 앞 10개 상태를 다시 비교하여 양쪽 총 20개 반복성 검사 통과.
- 원본 3축 구면/D6와 MuJoCo XYZ hinge, static/dynamic 마찰, weld 반력,
  mocap/kinematic contact velocity는 완전한 일대일 대응이 아니다.
- 관통 검사는 capsule/sphere와 제한된 스텝 사이 보간이다. mesh까지 연속 충돌 안전 인증이 아니다.
- 파단 반력 환산·자동 detach, 전체 로봇, 병렬 MuJoCo, RL/탐색은 구현하지 않았다.
  원본 파단 임계값 3N/0.08N·m와 후속 설계는 [CONVERSION.md](CONVERSION.md)에 기록했다.

**판단:** 메모리와 별도 최적화 모델의 처리량에는 이점이 있다. 하지만 원본 충실도와
속도를 함께 요구한다면 지금 바로 전체 시스템을 MuJoCo로 교체할 근거는 약하다.
계속 진행한다면 원본 120Hz 부착 제약 오차와 접촉 구동 방식 차이를 먼저 줄이고,
그 뒤 안정성이 확인된 모델로 병렬 처리량을 측정하는 순서가 적절하다.

## 추가 실험: Isaac 로봇 팔을 넣었을 때의 비용

[비교표·최종 화면](outputs/20260922_044331_robot_cost/index.html) ·
[CSV](outputs/20260922_044331_robot_cost/comparison.csv) ·
[보존용 검증 JSON](validation/robot_cost.json)

후보49의 **첫 10초**, full 식물·CPU 240Hz·PGS 64/4·파단 비활성 조건이다.
관절 명령을 재생하므로 새 IK/경로 계산은 없다. 고리 단독 조건은 실제 팔에서 측정한
고리 궤적을 직접 재생했다. GUI는 동일한 960×720 카메라와 30Hz 화면 갱신을 사용했다.

| 조건 | 10초 동작 처리 시간 | physics step | 화면 갱신 |
|---|---:|---:|---:|
| 고리만, 화면 없음 | 9.87초 | 9.34초 | — |
| 팔 포함, 화면 없음 | 10.78초 | 9.62초 | — |
| 고리만, 화면 표시 | 18.62초 | 10.36초 | 7.55초 |
| 팔 물리 포함, 팔 외형 숨김 | 20.41초 | 10.58초 | 8.44초 |
| 팔 물리 포함, 팔 외형 표시 | 21.24초 | 10.58초 | 9.25초 |

준비·검사·저장은 표의 실행 시간에서 제외했다. 나머지는 명령 업로드·상태 기록 등이다.
화면 갱신에는 USD 자세 동기화와 sim.render가 포함되며 순수 GPU 작업 시간은 아니다.
식물의 시각 형상은 비교용 proxy와 열매 mesh이므로 기존 하우스 전체 GUI와 동일하지 않다.

- 팔 물리·제어 추가: 약 **0.91초(+9.2%)**. 순수 physics step 차이는 약 **0.29초**였다.
- 팔 외형 표시 추가: 약 **0.83초(+4.1%)**. 숨김/표시의 전체 물리 상태는 완전히 같았다.
- 고리 단독과 팔 포함의 고리 궤적 최대 차이는 **0.00015mm 미만**이었다.
- 팔 포함 세 조건의 관절/식물/고리 상태는 같았다. 고리 단독은 kinematic이고 팔은 dynamic이므로
  식물 반응에는 최대 약 **1.22mm** 차이가 있었다. 접촉 구동 방식까지 동일하다는 뜻은 아니다.
- 모두 접촉이 있었고 관통·부착 오차 0.5mm 기준을 통과했다. 각 조건 한 번씩 측정했다.
- 경로 검증 과정에서 발견한 초기 1스텝 고리 위치 동기화 문제를 수정하고,
  고리 headless를 재측정했다. `*_failed_*` 폴더는 최종 비교에서 제외했다.

**이번 조건에서 팔 자체는 큰 병목이 아니었다.** 화면 갱신 전체 비용이 더 컸다.
기존 실행기가 느렸던 이유를 팔만으로 설명할 수 없으며, Hz·경로 계획·판정/상태 처리·
원본 시각 mesh 갱신 등의 차이도 남는다. 다음 단계는 로봇 포함 headless 조건에서
1/4/16환경의 처리량을 비교하는 것이 적절하다.
