## 이번에 실제로 달라진 것

- 마지막 자세 보정만이 아니라 하부 중심 통과, 측면 열린 입구 진입, 좌/우 휘어진 접근, 과실 상대 회전의 다섯 경로군을 생성한다.
- 경로의 실제 위치·회전 경유점이 달라지며 기존 pose-waypoint 계획기에 전달된다. 명칭만 다른 다섯 직선 후보가 아니다.
- 여러 장면·여러 타깃 스냅샷을 받아 기존 IK/FCL → 환경 검사 → 물리 실행 → 결과 집계 → 대표 영상 렌더를 호출한다.
- 기본 20개 거친 제안에서 여러 경로군을 번갈아 검토하고, 가능성이 보인 서로 다른 경로군 최대 2개에서 후속 제안을 각각 2개 만든다. 물리 실행은 타깃당 기본 최대 12회다. 제안 거절·계획 실패·검사 차단·물리 실행·예산 미평가를 구분한다.
- 목표 과실 및 목표 송이 자신의 중심가지 접촉을 opt-in 탐색 정책에서 허용한다. 정확한 바디 소속과 이름을 검사하므로 다른 송이의 동명 가지를 함께 허용하지 않는다.
- 여러 송이의 `truss_01__` 접두어가 있는 과실·꼭지 매핑을 처리한다.
- 기하 후보, 접촉 기반 유지 증거, 완주했으나 증거 없음, 경로 차단, 물리/실행 오류를 분리한다. 미발견을 불가능으로 바꾸지 않는다.

새 탐색은 독립 opt-in 흐름이다. 기존 azimuth-only 수집을 조용히 바꾸거나 `mjlab-performance`에 병합하지 않았다. 기존 RGB-D 학습기·action14·생산 정책·로봇 제어·물성·충돌 형상은 변경하지 않았다.

## 테스트가 입증하는 것과 입증하지 않는 것

순수 기하 시험은 경로군별 차이, 휘어진 위치 경유점, 위치와 회전이 함께 움직이는 pivot, 좌표 이동 일관성, 입력 보존, 표본 및 실행 예산, 상태 분류를 검사한다.

새 native 시험은 두 송이가 있는 작은 MuJoCo 모델에서 자기 송이 중심가지만 선택하는지 확인한다. 기존 native 접촉·거리·고리 형상 회귀도 함께 통과했다.

오케스트레이션 시험 일부는 계획기/물리 실행 자식 프로세스를 테스트용 함수로 대체해 호출 인자·결과 수집·예산·재사용 계약을 확인한다. **전체 온실에서 IK와 물리를 끝까지 실행한 통합 시험은 아니다.** 새 경로의 실제 성공률, 처리속도, 서버 렌더 결과 및 새로운 고리걸기 영상은 아직 확보하지 않았다.

현재 곡선은 여러 Cartesian 구간이며 기존 계획기가 구간마다 감속·정지를 넣는다. 사람처럼 연속적으로 부드러운 관절 동작이 완성된 것은 아니다. 초기 preapproach는 기존 관절 보간이며, 임의의 장애물 배치에 대해 경로를 반드시 찾아내는 완전한 계획기를 구현한 것은 아니다.

## 성공/실패 해석

`geometric_candidate`는 기존 1.5mm 후보 범위에 실제 실행 중 들어왔다는 뜻이다. 잠깐 들어온 경우와 hold/verify 동안 유지된 경우의 시간 이력은 원자료에서 구분한다. 이 범위를 실물 오차로 보정했다는 주장도, 기계적 수확 성공 주장도 아니다.

`contact_retention_evidence`는 기존 접촉·시간 판정의 더 강한 SIM 증거다. 모션 완주·실물 안전·파단 수확·다양한 장면 일반화까지 자동으로 보장하지 않는다.

모든 경우 `hook_success=null`, `training_eligible=false`를 유지한다. 이번에 불가능성 증명기를 구현한 것은 아니므로 `impossible=null`이다. 실패 단계와 충돌 대상을 보존해, 특정 후보 실패와 대상 자체의 불가능성을 혼동하지 않게 했다.

## 서버에서 다음 라운드의 완료 조건

1. 기존 미커밋 변경을 보존하고 별도 worktree에서 시작한다. 현재 branch/HEAD를 보고하고 위 코드가 포함됐는지 확인한다.
2. 다른 타깃 2개에서 smoke를 한다. 경로군당 2제안, 물리 타깃당 최대 6회, 부모 추가탐색 0, 대표 영상 3개. 가능하면 한 타깃은 두 번째 송이에 속하게 한다.
3. 코드/자산 연결 오류가 없는 것을 확인하면 새 6장면 × 3타깃 파일럿으로 넘어간다. 경로군당 4제안, 후속 제안 최대 4개, 전체 물리 타깃당 최대 12회다. 초기 검사 탈락 장면과 선택되지 않은 열매도 기록한다.
4. 04번 마지막 1.4mm를 해결하는 것을 이 파일럿의 선행조건으로 삼지 않는다. 반대로 가까이 있다는 이유로 성공을 선언하지도 않는다.
5. 각 경로군의 제안·IK·전경로 검사·실제 실행·완주·기하 후보·접촉 증거·오류·중단 수를 표로 만든다. 대표 영상에서 접근 방향과 고리 회전이 실제로 다르게 실행되는지 확인한다.
6. 동일 타깃의 기존 azimuth-only 경로는 비교 기준으로 유지한다. 접촉 정책이 달랐던 과거 결과와 새 수치만 직접 비교해서 성능 향상을 주장하지 않는다. 가능한 범위에서 같은 정책/물성/평가 지표로 비교한다.
7. 파일럿이 정상적으로 끝나면 대상 전체 열매와 장면 수를 늘리는 다음 계획을 제안한다. 지금 단계에서 대형 RL 재학습이나 불확실한 성공 라벨의 RGB-D 학습을 시작하지 않는다.

힘/변위 5N·20mm는 이전 실행과 비교하기 위한 첫 실험 중단값이지 실물 손상 한계가 아니다. 새 정책의 목표 힘 합에는 허용된 자기 Rachis 접촉도 포함된다. 서버에서 이 분류가 실제 접촉 기록과 맞는지 확인한다. 다른 과실·다른 송이·주줄기·거터·마운트/팔 접촉은 별도로 남기고 물성을 바꿔 통과시키지 않는다.

새 장면 준비 wrapper는 RGB-D 촬영까지 수행하지 않는다. 기존 collection을 사용할 때는 observation_path를 보존하며, 새 장면의 RGB-D는 탐색 실행이 안정된 후 기존 관측 수집기로 연결한다. 이를 숨겨진 꼭지 GT가 없는 실제 센서 추론 문제의 해결로 표현하지 않는다.
