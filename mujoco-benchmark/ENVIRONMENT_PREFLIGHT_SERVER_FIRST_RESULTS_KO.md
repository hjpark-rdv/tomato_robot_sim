작성: 2026-09-27. 대상 커밋 `38cdb6a`, 로컬 브랜치 `mjlab-performance`에 fast-forward 반영.

## 결론

- 실제 온실에서 알려진 거터/주줄기 충돌 경로를 사전검사가 거절했다. 실행 보류 연결도 실제 모델로 확인했다.
- 기존 중심 진입 성공 경로도 거절됐다. 검출된 동일 물체 쌍을 새 물리에서 확인하니 명목 계획 검사와 차이가 있었다. 정책을 완화하거나 물체를 제외하지 않았다.
- 전체 7경로 모두 blocked. 전체 길이 sampled_clear 경로의 통과 후 물리 검증은 아직 없다. 첫 1초 통과 시험을 전체 성공으로 해석하면 안 된다.
- 주변 송이106개·잎은 운영 모델에서 여전히 시각 전용이다. 검사기의 정확성과 검사 대상의 완전성은 별개다.

## 방법 및 보존

기존 각도/계획/물리 설정/성공 기준을 수정하지 않았다. 예제 clearance=0m, 허용 접촉 없음. 모델당 실제 collision geometry를 조회했다. 로컬 MuJoCo 관련 자동 테스트46개 통과(0.62초).

7개 기존 run의 manifest/model/reference/trace/plan/result/states 파일을 검사 전후 SHA256 비교해 불변 확인했다. 검사 중 RobotEngine qpos도 불변 확인. 출력은 별도 폴더다. bundle 파일 등 사용자 미추적 파일은 건드리지 않았다.

검출된 자세를 MuJoCo EGL로 렌더하여 대상 쌍을 육안 확인했다. 빨강은 도구 충돌체, 청록은 환경 충돌체. planned는 초기 식물을 고정한 계획 자세, recorded는 가장 가까운 저장 시각의 실제 qpos다. 물체 쌍만 표시한 그림은 설명용이며 충돌 모델을 수정한 것이 아니다. 이번 검증은 이미지 렌더링이며 대화형 GUI 조작 시험은 하지 않았다. 작은 침투량의 판정은 픽셀 대신 부호 있는 거리 재조회로 확인했다.

## 성공 기록의 새 물리 진단

gutter02를 별도 진단으로 같은 명령/240Hz에서 41.85초, 10,044스텝 실행했다. 사전검사를 통과한 실행으로 꾸민 것이 아니며 운영 gate를 바꾸지 않았다. 성공 기록과 계획 검사의 차이를 조사하기 위한 별도 RobotEngine 재실행이다.

- 실제 계산 17.697초, 물리 유효성 기준 통과, 발산 없음.
- 사전 거절 쌍 g390 / glb_col_TRUSS_Rachis_05는 매 스텝 거리 조회에서 최소 0.866435mm. 이 새 실행의 해당 쌍은 기하학적으로 겹치지 않았다.
- 로봇–환경의 contact.dist<=0 기록은 없었으나, 고리 contact 기록은 6,397스텝에 존재했다. 접촉 margin 등의 영향으로 양의 거리에서도 접촉 제약/힘이 있을 수 있다. 힘을 직접 집계하지 않았으므로 무접촉/무힘을 입증한 것이 아니다.
- 새 진단은 상태 저장과 중심 진입 재분류를 수행하지 않았다. 이전의 partial_center_entry와 새 진단 결과를 구분한다.

**Pro 검토 요청:** 초기 식물 고정 검사에서 거절되지만 실제 해당 쌍은 간격을 유지하는 사례를 어떻게 다룰 것인가? 거리 여유를 줄이거나 가지를 통째로 허용하는 방식으로 통과시키지 말고, 명목 검사·추종/변형·접촉 margin·실제 접촉력 기준을 분리해 검토해 달라.

## 다음 작업 제안과 미검증 사항

1. 사용자 요구가 있는 로봇 주변 송이·과실의 고정 충돌 형상을 연결하고 초기 배치 겹침을 별도로 검사한다. 현재 연구 범위에서 잎까지 금지할지도 명시한다.
2. 금지 접촉 판정에서 기하 거리, MuJoCo contact 생성, 유효 접촉력 중 무엇을 의미하는지 정의하고 각각 로그를 남긴다.
3. 목표 꼭지의 어느 구간을 어떤 단계에서 허용할지는 사용자 확인 후 최소 쌍으로 지정한다. 이번 시험은 어떤 쌍도 자동 허용하지 않았다.
4. 실제 팔꿈치만 충돌하는 온실 사례, 상승 중 비목표 과실 접촉 사례는 아직 별도 확보하지 못했다. 작은 native fixture 테스트 통과와 구분한다.
5. 전체 sampled_clear 경로를 확보하면 새 물리에서 감시한다. 지금 결과로 false-positive/false-negative 비율을 계산할 수 없다.
6. 그 후 막힌 구간의 경로 보정 도입 범위를 결정한다. 이번 검증에서는 각도/기울기/경로를 보정하지 않았다.

## 전달 파일

`index.html`: 계획/기록 비교 이미지와 각 검사 JSON 링크.
`results.json`: 각 사례 원본 검사·inventory·기존 metrics·모델/trace hash·상태 비교.
`policy.json`: 사용 정책, `gate_results.json`: 실행 연결, `fresh_success_diagnostic.json`: 새 물리 진단.
`verify.py`, `analyze.py`, `gate.py`, `diagnose_success.py`: 해당 서버 자산에서 재현한 스크립트. 같은 output을 재사용하지 말고 새 폴더에 복사해 실행할 것.

원본 대형 모델/학습 데이터는 공유 ZIP에 포함하지 않는다. 각 결과 source_run 및 해시로 식별한다.
