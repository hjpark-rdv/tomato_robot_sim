## 재사용과 서버 수정

기존 랜덤 GLB 생성기 → scene-only snapshot → pose-waypoint IK/FCL/로봇 검사 → 환경 검사 → RobotEngine → 접촉 기록 → 저장 qpos 렌더를 사용했다. 새로운 물리 엔진·제어기·학습 파이프라인은 추가하지 않았다.

1. 환경 검사에서 매 표본마다 544개 허용 쌍을 선형 검색하던 부분을 `(robot geom, environment geom) → 허용 phase 집합`으로 한 번 구성했다. 중복 쌍의 phase 합집합과 경계 처리를 회귀 검증했다. 같은 smoke trace의 120초 시간초과(6,251표본, 경로 중 46.3초까지)가 전체 7,418표본/약38초 완료로 바뀌었고 첫 위반은 동일하다. 시간초과 원본은 별도 폴더에 보존했다.
2. 서버 로컬 디스크 여유 부족으로 새 대형 자산만 NAS에 저장했다. 반복 읽기 병목은 SHA256 검증된 동일 MJB의 RAM 캐시로 줄였다. 완료 시 새 run의 모델 링크는 NAS 원본으로 되돌린다. source asset이나 물리는 바뀌지 않는다.
3. 허용한 자기 송이 중심가지와 목표 꼭지의 비안착 접촉 힘도 요약/영상에 표시한다. 금지 물체와 접촉 임계값은 유지했다.
4. 기존 azimuth-only trace 비교용 opt-in phase 별칭을 추가했다. `entry→approach`, `rise/rise_mid→seat`, `pull→verify`이며 시간·관절명령은 원본 그대로다. 원본 trace와 평가 trace를 모두 보존한다.
5. `side_mouth`의 준비점이 송이 반대쪽에 잡히는 공통 원인을 발견했다. `--families side_mouth --robot-facing-mouth`에서만 열린 +X 입구가 목표 쪽을 향하고 준비점이 로봇 쪽에 놓이도록 회전과 위치를 함께 바꿨다. 이 모드는 최종 고리 방향도 달라지므로 준비점 위치만의 효과를 분리한 실험은 아니다. 기본 5종 생성 결과와 다른 4종은 회귀에서 동일하다. 같은 4개 Sobol 파라미터를 재사용한 비교이며 새로운 무작위 표본이나 마지막 mm 보정이 아니다.
6. 읽기 전용 전체 결과 집계와 저장 관절명령의 FK 확인 도구를 추가했다. 계획 FK와 실제 추종은 구분한다.

물성, collision mask, margin/gap, 마찰, 강성, actuator, 0.5mm 물리 유효성 기준은 변경하지 않았다. 허용 접촉의 힘 크기 합 5N, 목표 과실 변위 20mm, 비허용 접촉 0.01N은 이번 실험의 중단 조건이다. 실물 안전 한계가 아니다.

## 접촉 매핑·물리 대조군

실제 native body 소속에서 반원 와이어32개, 해당 목표 과실, 목표 꼭지, 자기 송이 Rachis14개를 확인했다. `truss_01__`의 다른 송이는 금지로 남는다. 예를 들어 Tomato_02의 distal anchor는 Attachment_01이며, Attachment_02는 Tomato_03 소속이다. 숫자 접미사만으로 타깃을 추정하지 않았다.

기존 경로 두 개는 재계획 없이 같은 search-contact-policy로 정상 시작에서 실행했다. 이는 실행기/정책 연결 대조이며 새 경로군의 발견 건수에 넣지 않는다.

| 기존 경로 | 실제 완주 | 과실 힘 최대 N | 자기 Rachis 힘 최대 N | 과실 최대변위 mm | 비허용 힘 N | 기하 표본 | 접촉 유지 증거 |
|---|---:|---:|---:|---:|---:|---:|---|
| seating_00_under | 예,20.600초 | 1.576 | 0 | 10.951 | 0 | 51 | 없음 |
| seating_03_under | 예,20.817초 | 1.502 | 1.227 | 10.377 | 0 | 853 | 없음 |

위 힘은 각 범주의 **poststep private forward 힘 크기 합의 최대**이며 서로 다른 시점의 최대를 더하지 않는다. 중단 감시는 live solve와 poststep private forward를 구분해 보존한다. legacy의 단일 법선력 최대와도 다른 측정량이다. 00의 times/qpos는 기존9ea72dd 실험과 bitwise 동일하다. 03은 자기 중심가지 접촉이 실제로 허용되지만 다른 물체 접촉이 허용된 것이 아님을 확인한다.

03의 hold는344표본/실제1.429167초, verify는398표본/1.654167초, 최대 표본 간격1/240초다. 기하 조건 표본이 있어도 의도한 꼭지 접촉력 조건이 없어 접촉 유지 증거는 false다. 두 경로 모두 정상 초기 자세에서 시작했고 physics_valid=true지만 수확 성공을 확정하지 않는다.

동일 gutter02/Tomato_02의 기존 azimuth-only `predicted_00000`도 같은 모델 SHA256,240Hz,접촉 정책으로 검사했다. 전체 검사 완료 후 다른 꼭지 `glb_col_TRUSS_Pedicel_proximal_03_00`와21.85초(rise→seat)에 충돌해 차단됐다. 과거 더 엄격한 정책의 성공률 숫자를 비교하지 않았고, 차단 경로를 실제 물리에 강제로 넣지 않았다.

## 해석과 후속 작업

기하 목표, IK와 로봇 검사, 전체 환경 검사, 실제 완주, 기하 후보, 접촉 유지 증거, 실제 수확은 서로 다른 단계다. 실행하지 않은 경로의 힘·변위는0으로 추정하지 않고 미측정으로 취급한다. `training_eligible=false`, `hook_success=null`, `impossible=null`을 유지했다. RGB-D/RL/기존 action14 학습 데이터에는 섞지 않는다.

**공통 prefix 확인:** under_center / flank_left / flank_right / pivot_sweep는 같은 표본에서 준비·접근 관절명령이 실제로 동일했다(48개 타깃×표본 그룹 전부 일치). 그중23그룹, 즉92경로는 분기하기 전부터 모두 막혔다. 전체 궤적이 서로 다르다는 것과 초기 접근이 독립적이라는 것은 다르다. 이92개로 우회·회전 자체의 우열을 평가할 수 없다. 원자료는 `prefix_comparison.json`에 있다.

최초 차단 중 목표 과실이나 자기 Rachis가 등장해도 허용 정책 오류는 아니었다. 해당 건의 로봇 접촉체는 허용된32개 와이어 이외의 로봇 충돌체였다(원래 파일럿11건, 측면 비교4건). 정확한 geom/body와 wire 여부를 `*_blockers.json`에 저장했다.

원래 파일럿 FK 최대 위치 오차는0.04744mm, 측면 비교는1.81888mm였다. 기존 IK 허용2mm를 통과했다는 것이1.5mm 안착 기하를 만족한다는 뜻은 아니다. 실제 추종·접촉 검증과 구분한다.

이번 일반화 범위는 제한된 파라미터·타깃의 SIM-GT 교사 탐색이다. 후보 전부 실패를 절대적인 수확 불가능으로 판정하지 않는다. 초기 탈락, 미선택, IK 미발견, 검사 차단, 실제 실행, 예산 미평가를 분리했다. 첫 위반만으로 전체 경로의 모든 충돌 물체를 설명하지 않는다. 전체 검사는 끝까지 수행하지만 원자료의 세부 위반 목록에는 저장 상한이 있다.
